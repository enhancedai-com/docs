You no longer add a model by editing enums, DTOs, a technologies file and a pricing seeder. The model catalog lives in the database (`system_ai_models` and `model_price`) and is kept up to date by a nightly sync from the [Vercel AI Gateway](https://vercel.com/docs/ai-gateway). The sync proposes new models and price changes; a system admin approves or rejects each proposal in the admin panel. Nothing a proposal describes reaches customers until someone approves it.

The sync shipped in back #1937 and front #2148 (2026-09-15). Back #2102 (2026-11-11) made the nightly run finish reliably and retire models their providers shut down.

## How the nightly sync works

`SyncAiModelsFromGatewayService` (`back/src/cronJobs/syncAiModelsFromGateway/`) runs `AiModelSyncService.sync()` every day at 04:00 under a cron lock, so only one API instance runs it. Each run is recorded in `ai_model_sync_runs`.

<Steps>
  <Step title="Read the gateway catalog">
    The sync reads the model list from `AI_GATEWAY_BASE_URL` (default `https://ai-gateway.vercel.sh/v1`). If the gateway returns fewer models than `AI_GATEWAY_MIN_CATALOG_SIZE` (default 100), the run aborts without writing anything.
  </Step>
  <Step title="Map each model to a provider we call">
    The gateway keys models by their creator. Only creators mapped in `GATEWAY_CREATOR_TO_AI_COMPANY` (`back/src/shared/ai-model-gateway/gateway-model-mapper.ts`) are considered: Anthropic, OpenAI, Google (`gemini`), xAI, Mistral, Perplexity and Moonshot. Text and image models are mapped; ids ending in `-fast` or `-batch` are skipped. A model is also skipped when its own creator does not serve it, or when we already serve it under another host, because we only call the creator's API.
  </Step>
  <Step title="Update models we already have">
    For a model already in `system_ai_models`, capability fields (token limits, context window, vision, reasoning, web search, structured output, streaming, temperature, description) are updated in place. `supportsImageOutput` is only ever raised to `true`, never lowered. A price that differs from the stored `model_price` row becomes an **update price** proposal; the stored price is not changed.
  </Step>
  <Step title="Propose new models">
    A model we do not have becomes an **add model** proposal in `ai_model_sync_proposals`, carrying its capabilities and prices. If the gateway price is missing or outside the accepted range, the proposal is flagged and approving it creates the model switched off.
  </Step>
  <Step title="Retire models that disappeared">
    A model missing from the gateway for `AI_GATEWAY_DEPRECATE_AFTER_MISSING_RUNS` consecutive runs (default 2) is deprecated automatically: it is archived in `system_ai_models_archive`, switched off, and, when `AI_GATEWAY_SYNC_REMAP_FLOWS` is not `false`, flow nodes and company technologies that used it are repointed at a replacement model. Groq and Cloudflare Workers AI models are checked against their own providers' catalogs the same way. If a whole catalog comes back empty, the sync treats it as a bad response and retires nothing.
  </Step>
  <Step title="Notify the reviewers">
    When proposals are waiting, the sync posts a message to the Google Chat webhook in `AI_MODEL_SYNC_CHAT_WEBHOOK_URL` with a link to the review queue. Without the webhook, the message goes to the log.
  </Step>
</Steps>

## Review the proposals

Proposals are reviewed by a system admin in the admin panel: **Admin → AI models → Sync** (`/admin/ai-models?tab=sync`; the older `/admin/ai-model-proposals` link redirects there). The tab shows a badge with the number of pending proposals and three sections:

| Section | What it lists | What approving does |
|---|---|---|
| New models | Models the gateway lists that we do not have | Creates the `system_ai_models` row and its `model_price` rows. The model is switched on only if the gateway sent a usable price; otherwise it is created switched off with no prices, and you price it and switch it on in **All models**. |
| Price changes | Prices that differ from what we store | Writes the new `fluxConversion` on the `model_price` row. A change bigger than `AI_GATEWAY_PRICE_CHANGE_ALERT_RATIO` (default 5x) is flagged, because it is usually a unit mistake. |
| Retired automatically | Models the last run deprecated | Nothing to approve; it is the record of what was retired and what replaced it. |

Each proposal shows a **reach** badge that says whether our worker and the completions API can actually call that provider and modality. A model whose provider we cannot call is flagged; approving it adds a model nobody can run.

Rejecting a proposal keeps it rejected: the next run does not raise the same model again, and a rejected price is raised again only if the provider changes it.

The queue is served by `GET /ai-model-proposals`, `GET /ai-model-proposals/runs` and `POST /ai-model-proposals/decide`, all behind `JwtAuthGuard` and `MasterUserGuard`.

## Add a model by hand

Use **Admin → AI models → All models → Create new model** for a model the gateway does not list, such as a model from a provider outside `GATEWAY_CREATOR_TO_AI_COMPANY`. The form sets the identity, price, limits and capabilities in one step. Do not insert rows with SQL and do not add the model to a seeder.

## When you need code

You only change code when the model needs something the platform cannot do yet:

- **A new provider.** Add it to the executable provider lists in `back/src/shared/ai-model-gateway/executable-providers.ts` and to the places that file's header lists (the worker text and image generators, `flow-node.service.ts`, and the front completion log providers). If the gateway should sync it, add its creator to `GATEWAY_CREATOR_TO_AI_COMPANY`.
- **A new capability flag** on `system_ai_models`. Add the column with a migration, and check that the admin AI Models page can set it (see the `system-ai-model-capability-sync` skill in the workspace).
- **A new modality**, such as a model type the sync does not map today.

## Run the sync by hand

A system admin can trigger a run with `POST /internal/ai-model-sync/run`. Pass `?dryRun=true` to compute the report without writing.

## Environment variables

| Variable | Default | Effect |
|---|---|---|
| `AI_GATEWAY_SYNC_ENABLED` | on | Set to `false` to stop the nightly run. `DISABLE_CRONS=true` also stops it. |
| `AI_GATEWAY_SYNC_DRY_RUN` | `false` | Compute the report without writing. |
| `AI_GATEWAY_SYNC_DEPRECATE` | `true` | Run the retirement pass. |
| `AI_GATEWAY_SYNC_REMAP_FLOWS` | `true` | Repoint flow nodes at the replacement when a model is retired. |
| `AI_GATEWAY_MIN_CATALOG_SIZE` | `100` | Abort the run below this many gateway models. |
| `AI_GATEWAY_PRICE_CHANGE_ALERT_RATIO` | `5` | Flag price changes bigger than this multiple. |
| `AI_GATEWAY_DEPRECATE_AFTER_MISSING_RUNS` | `2` | Consecutive missing runs before a model is retired. |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | unset | Enable the Cloudflare Workers AI price and retirement pass. |
| `AI_MODEL_SYNC_CHAT_WEBHOOK_URL` | unset | Google Chat webhook for the review message. |
| `AI_MODEL_SYNC_REVIEW_URL` | production admin queue | Link the review message points at. |
