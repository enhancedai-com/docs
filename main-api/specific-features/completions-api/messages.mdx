---
title: "Messages (Anthropic-compatible)"
description: "POST /v1/messages and POST /v1/messages/count_tokens — Anthropic Messages API compatible endpoints that run any model FluxPrompt supports, so Anthropic SDKs and Claude Code work against FluxPrompt."
---

The Messages endpoints speak the Anthropic Messages API. Send an Anthropic-format request and FluxPrompt resolves the provider from the `model` id, runs the model, and returns an Anthropic-format message. You can use any model FluxPrompt supports, not only Claude models.

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/messages` | Run a message, as a single response or a stream. |
| `POST` | `/v1/messages/count_tokens` | Count the input tokens of a Messages request. |

Behind the scenes, FluxPrompt translates the request into the same pipeline as [Chat completions](/main-api/specific-features/completions-api/chat-completions). Model gating, the credit check, image handling, billing, and [Completion logs](/main-api/specific-features/completions-api/completion-logs) are shared between both endpoints.

## Authentication

Send your FluxPrompt API key in any one of these headers:

| Header | Example |
| --- | --- |
| `x-api-key` | `x-api-key: <your-api-key>` |
| `Authorization` | `Authorization: Bearer <your-api-key>` |
| `api-key` | `api-key: <your-api-key>` |

Anthropic SDKs send `x-api-key` by default, so you only change the base URL. A missing or invalid key returns `401`.

## Use with the Anthropic SDK and Claude Code

Point the client at `https://api.fluxprompt.ai` and use your FluxPrompt API key.

<CodeGroup>

```python Anthropic SDK (Python)
import anthropic

client = anthropic.Anthropic(
    base_url="https://api.fluxprompt.ai",
    api_key="<your-api-key>",
)

message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=256,
    messages=[{"role": "user", "content": "Summarize the theory of relativity in one sentence."}],
)
print(message.content[0].text)
```

```bash Claude Code
export ANTHROPIC_BASE_URL="https://api.fluxprompt.ai"
export ANTHROPIC_AUTH_TOKEN="<your-api-key>"
claude
```

</CodeGroup>

<Note>
FluxPrompt accepts what Claude Code sends: system messages inside `messages`, thinking settings with extra fields, long tool descriptions (up to 100,000 characters), the `anthropic-beta` header, `metadata.user_id`, `context_management`, and the `x-claude-code-session-id` header. See [Request](#request) for the details.
</Note>

## Request

### Headers

```http
x-api-key: <your-api-key>
content-type: application/json
```

Optionally, send `anthropic-beta`, and `x-session-id` or `x-claude-code-session-id`. FluxPrompt forwards the beta header with the request, and uses the session identifier for [prompt caching](#prompt-caching).

### Body

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `model` | string | yes | The model id. Any model from [List models](/main-api/specific-features/completions-api/list-models). |
| `max_tokens` | integer | yes | At least 1. Capped at the model's maximum output tokens, and at 16,384 for a non-streamed request. |
| `messages` | array | yes | Anthropic messages. See [Messages and content blocks](#messages-and-content-blocks). |
| `system` | string \| array | no | A string, or an array of text blocks. |
| `tools` | array | no | Custom tools: `{ name, description, input_schema }`. See [Tools](#tools). |
| `tool_choice` | object | no | `auto`, `any`, `tool` (with `name`), or `none`. See [Tools](#tools). |
| `temperature` | number | no | From 0 to 1. |
| `top_p` | number | no | From 0 to 1. |
| `stop_sequences` | array of strings | no | Up to 4 sequences of at most 100 characters each. |
| `stream` | boolean | no | Defaults to `false`. See [Streaming](#streaming). |
| `thinking` | object | no | Extended thinking. FluxPrompt forwards only `type` and `budget_tokens`. |
| `cache_control` | object | no | A prompt cache marker for the request. See [Prompt caching](#prompt-caching). |
| `metadata` | object | no | FluxPrompt reads `metadata.user_id` and forwards it with the request. |
| `context_management` | object | no | Context management edits, forwarded with the request. |

Fields that are not in this table, such as `top_k`, are ignored.

### Messages and content blocks

Each message has a `role` and a `content`. The `content` is a string or an array of blocks. `role` is `user`, `assistant`, or `system`; a `system` message inside `messages` is treated like the `system` field.

| Role | Supported blocks | Notes |
| --- | --- | --- |
| `user` | `text`, `image`, `tool_result` | An `image` block has a `base64` source (with `media_type` and `data`) or a `url` source. |
| `assistant` | `text`, `tool_use` | `thinking` and `redacted_thinking` blocks are accepted and ignored. |

- Any other block type returns `400` with the Anthropic error type `invalid_request_error` and a message such as `unsupported user content block 'document'`.
- A `tool_result` block answers the `tool_use` block with the same id. `content` is a string or an array of text blocks. When `is_error` is `true`, FluxPrompt prefixes the result with `Error: `.
- Images follow the same rules as [Chat completions](/main-api/specific-features/completions-api/chat-completions#content-parts): an `https` URL or a base64 image of at most 20 MB, in a user message, on a model that accepts images.
- The [limits of Chat completions](/main-api/specific-features/completions-api/chat-completions#limits) apply to the translated request. Each `tool_result` block counts as its own message.

### Tools

- Only custom tools are supported. A tool with a `type` other than `custom` (for example, a server tool) returns `400` with `tool type 'X' is not supported`.
- `tool_choice.type` maps as `auto` to `auto`, `any` to `required`, `none` to `none`, and `tool` with a `name` to that named tool.
- `disable_parallel_tool_use` on `tool_choice` turns parallel tool calls off.
- The model must support tool calling, otherwise the request fails with `400 model_not_tool_capable`.

### Prompt caching

Add `cache_control` to the top level of the request, to a `system` text block, to a content block, or to a tool. The rules match [Prompt caching](/main-api/specific-features/completions-api/chat-completions#prompt-caching) on Chat completions:

- `type` is `ephemeral`, and `ttl` is `5m` or omitted. A `1h` TTL returns `400`.
- Anthropic models accept at most four cache markers.
- FluxPrompt picks the cache session key from the `x-session-id` or `x-claude-code-session-id` header. When you send neither, FluxPrompt derives one from your account, the first system message, the first user message, and the tool names.

### Example

<CodeGroup>

```bash cURL
curl -X POST "https://api.fluxprompt.ai/v1/messages" \
  -H "x-api-key: <your-api-key>" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 256,
    "system": "You are concise.",
    "messages": [
      { "role": "user", "content": "Summarize the theory of relativity in one sentence." }
    ]
  }'
```

```json Tool use request
{
  "model": "claude-sonnet-4-6",
  "max_tokens": 1024,
  "tools": [
    {
      "name": "get_weather",
      "description": "Get the current weather for a city.",
      "input_schema": {
        "type": "object",
        "properties": { "city": { "type": "string" } },
        "required": ["city"]
      }
    }
  ],
  "messages": [
    { "role": "user", "content": "What is the weather in Lisbon?" }
  ]
}
```

</CodeGroup>

## Response

On success, returns an Anthropic `message` object.

```json
{
  "id": "msg_1718600000123",
  "type": "message",
  "role": "assistant",
  "model": "claude-sonnet-4-6",
  "content": [
    { "type": "text", "text": "Spacetime tells matter how to move, and matter tells spacetime how to curve." }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 28,
    "output_tokens": 16
  }
}
```

### Response fields

<ResponseField name="id" type="string">
  The message identifier, prefixed with `msg_`.
</ResponseField>

<ResponseField name="content" type="array">
  The output blocks. A `text` block holds the generated text, and one `tool_use` block (`id`, `name`, `input`) is returned for each tool call. Thinking blocks are not returned.
</ResponseField>

<ResponseField name="stop_reason" type="string">
  `end_turn` (natural end), `max_tokens` (hit `max_tokens`), or `tool_use` (the model called a tool). A response that contains a `tool_use` block always has `stop_reason: "tool_use"`.
</ResponseField>

<ResponseField name="stop_sequence" type="null">
  Always `null`.
</ResponseField>

<ResponseField name="usage" type="object">
  `input_tokens` and `output_tokens`, plus the cache fields below when the provider reports cache activity.
</ResponseField>

### Cache usage

| Field | Meaning |
| --- | --- |
| `usage.input_tokens` | Input tokens that were neither read from nor written to the cache. |
| `usage.cache_read_input_tokens` | Input tokens read from the cache. Present when greater than 0. |
| `usage.cache_creation_input_tokens` | Input tokens written to the cache. |
| `usage.cache_creation.ephemeral_5m_input_tokens` | Cache write tokens in the 5-minute cache. |
| `usage.cache_creation.ephemeral_1h_input_tokens` | Cache write tokens in the 1-hour cache. |

<Warning>
On `/v1/messages`, `input_tokens` excludes cached tokens, as on Anthropic's API. On `/v1/chat/completions`, `prompt_tokens` includes them. Add the cache fields to `input_tokens` to compare the two.
</Warning>

## Streaming

Set `stream: true` to receive Anthropic server-sent events. The response is `200` with `Content-Type: text/event-stream`.

| Event | When |
| --- | --- |
| `message_start` | The stream opens. It carries the message envelope, and `usage` with the real input and cache token counts when they are known at that point. |
| `ping` | Every 15 seconds while the stream is open. |
| `content_block_start`, `content_block_delta`, `content_block_stop` | Once for the text block (with `text_delta` deltas), then once for each tool call. |
| `message_delta` | The end of the message. It carries `stop_reason` and the final `usage`. |
| `message_stop` | The stream is complete. |
| `error` | A failure happened after the stream opened. |

- Text arrives incrementally as `text_delta` events.
- Each tool call arrives as a complete `tool_use` block after the text. Its input is sent in one `input_json_delta` event, not split into fragments.
- Reasoning is not streamed.

```text Event stream
event: message_start
data: {"type":"message_start","message":{"id":"msg_1718600000123","type":"message","role":"assistant","model":"claude-sonnet-4-6","content":[],"stop_reason":null,"stop_sequence":null,"usage":{"input_tokens":0,"output_tokens":0}}}

event: content_block_start
data: {"type":"content_block_start","index":0,"content_block":{"type":"text","text":""}}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Spacetime tells matter how to move."}}

event: content_block_stop
data: {"type":"content_block_stop","index":0}

event: message_delta
data: {"type":"message_delta","delta":{"stop_reason":"end_turn","stop_sequence":null},"usage":{"input_tokens":28,"output_tokens":16}}

event: message_stop
data: {"type":"message_stop"}
```

The same timing rules as [Chat completions streaming](/main-api/specific-features/completions-api/chat-completions#streaming) apply. The stream opens on the first output or after 10 seconds, a failure before the stream opens returns a regular JSON error, and a streamed request can run for up to 12 minutes.

## Count tokens

`POST /v1/messages/count_tokens` returns the number of input tokens a Messages request would use, without running the model.

The body is the same as `POST /v1/messages`, without `max_tokens` and `stream`.

```bash cURL
curl -X POST "https://api.fluxprompt.ai/v1/messages/count_tokens" \
  -H "x-api-key: <your-api-key>" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      { "role": "user", "content": "Summarize the theory of relativity in one sentence." }
    ]
  }'
```

```json Response
{ "input_tokens": 14 }
```

How FluxPrompt counts:

- For Anthropic, Gemini, OpenAI, xAI, and Moonshot models, FluxPrompt asks the provider for the token count.
- For other models, for an unknown model id, or when the provider does not answer within 3 seconds or fails, FluxPrompt returns a local estimate instead of an error. The estimate is padded by 15%.
- FluxPrompt caches the answer for identical requests for 10 minutes.
- Counting does not run the model, and it does not bill your account or create a completion log.

<Info>
Treat the count as an estimate for budgeting. The model's own `usage` on the final response is the authoritative count.
</Info>

## Errors

Errors use the Anthropic envelope:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "Model 'gpt-unknown' not found."
  }
}
```

The error `type` follows the HTTP status:

| HTTP | `error.type` | Cause |
| --- | --- | --- |
| `400` | `invalid_request_error` | Invalid body, unknown model, unsupported block, unsupported tool type, images or tools on a model that does not support them, or a context overflow. |
| `401` | `authentication_error` | Missing or invalid API key. |
| `402` | `billing_error` | No active subscription or no remaining credits. |
| `403` | `permission_error` | The model is disabled for your company or space. |
| `404` | `not_found_error` | The resource was not found. |
| `413` | `request_too_large` | The request is too large. |
| `429` | `rate_limit_error` | The provider rate-limited the request. The `retry-after` header holds the seconds to wait. |
| `504` | `timeout_error` | The request timed out. |
| `529` | `overloaded_error` | The provider is overloaded. |
| other | `api_error` | An unexpected error. |

A prompt that exceeds the model's context window returns `400` with a message such as `prompt is too long: 215000 tokens > 200000 maximum`, matching Anthropic's wording.

For the detailed causes behind each `400`, see the [Chat completions error table](/main-api/specific-features/completions-api/chat-completions#errors). The Anthropic envelope carries the message and type, but not the OpenAI `code`.
