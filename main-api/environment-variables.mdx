## Obsolete

In `.env.example` but unused, safe to remove: `TYPEORM_SYNCHRONIZE`, `EMAIL_SSL`, `EMAIL_TLS`, `STRIPE_ACCOUNT_ID`.

## Cross-repo gotcha

`MCP_INTERNAL_SECRET` and `MCP_OAUTH_CONSENT_SECRET` must be identical to the values in `mcp-server` — same SSM param in every environment, or MCP calls 500 / OAuth consent fails silently.

`INTEGRATIONS_ENCRYPTION_KEY` must be identical to `worker`'s value — same SSM param in every environment, and it must never be set to `JWT_SECRET`. The worker decrypts `user_integrations` rows written by `back` (Stripe adapter, P0+Stripe migration `868ke6j3r`) using its own copy of this helper, which has no `JWT_SECRET` fallback.

## CI/CD

Runtime vars are not baked into the Docker image at build/CI time — they live in the ECS task definition (backed by SSM), fetched fresh on every deploy. The GitHub Actions workflow itself only needs 2 repo secrets: `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`, both confirmed present.
