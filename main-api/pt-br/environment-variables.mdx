## Obsoletas

Estão no `.env.example` mas sem uso, pode remover: `TYPEORM_SYNCHRONIZE`, `EMAIL_SSL`, `EMAIL_TLS`, `STRIPE_ACCOUNT_ID`.

## Pegadinha cross-repo

`MCP_INTERNAL_SECRET` e `MCP_OAUTH_CONSENT_SECRET` precisam ser idênticas ao valor no `mcp-server` — mesmo parâmetro SSM em todo ambiente, senão as chamadas MCP dão 500 / o consentimento OAuth falha silenciosamente.

`INTEGRATIONS_ENCRYPTION_KEY` precisa ser idêntica ao valor do `worker` — mesmo parâmetro SSM em todo ambiente, e nunca pode ser `JWT_SECRET`. O worker descriptografa linhas de `user_integrations` gravadas pelo `back` (adapter Stripe, migração P0+Stripe `868ke6j3r`) usando sua própria cópia desse helper, que não tem fallback pro `JWT_SECRET`.

## CI/CD

As vars de runtime não são injetadas na imagem Docker em tempo de build/CI — elas vivem na task definition do ECS (respaldada por SSM), buscada fresh a cada deploy. O workflow do GitHub Actions em si só precisa de 2 secrets do repo: `AWS_ACCESS_KEY_ID` e `AWS_SECRET_ACCESS_KEY`, ambos confirmados presentes.
