This page names every stop in the run lifecycle and points to where each stop lives in code. The ordered diagrams for the two run modes (full flow and single-node) live on the published pipeline page, and this page is the verbal index into them. It does not restate the pipeline — it tells you which file and symbol to open when a particular stop misbehaves.

## The eight stops

A run flows through eight observable stops:

1. **Entry endpoint** — the back receives the run request.
2. **`node_executions` row** — a row is created, keyed by `(execId, nodeId)`.
3. **Temporal dispatch** — the back enqueues the workflow.
4. **`fetchNodeRow`** — the worker activity reads the row.
5. **Execute** — the node module runs.
6. **`persistNodeSuccess`** — the worker activity writes the output row.
7. **Redis signal** — the back is notified of completion.
8. **Socket emit** — the front receives the update.

## What you observe at each stop

| # | Stop | `node_executions` row state | Temporal UI event | Worker log |
|---|---|---|---|---|
| 1 | Entry endpoint | row not yet created | — | — |
| 2 | Row created | `input` populated by the API, `outputData` empty, `isError: false` | — | — |
| 3 | Temporal dispatch | unchanged | `WorkflowExecutionStarted` | — |
| 4 | `fetchNodeRow` | unchanged (worker reads `input`) | `ActivityTaskStarted` on `fetchNodeRow` | log entry with `execId`, `nodeId` |
| 5 | Execute | unchanged (worker in-memory) | activity running | log entry with `type` |
| 6 | `persistNodeSuccess` | `outputData` populated, `output` set, `isError` set, `updatedAt` bumped | `ActivityTaskCompleted` on `persistNodeSuccess` | log entry with duration |
| 7 | Redis signal | unchanged | — | — |
| 8 | Socket emit | unchanged | — | — |

<Note>
The `node_executions` entity does **not** have a `status` column. State is observed via the combination of `input` presence (set by the API at row creation), `outputData` presence (set by `persistNodeSuccess`), `isError` (set at the same time as `outputData`), and `cancelledAt` (set when a run is cancelled). See [Running and debugging locally](/worker/running-locally) for the SQL and the full set of columns.
</Note>
