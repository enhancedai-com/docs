## Overview

The **AI Text Generator** node produces LLM output using the Vercel AI SDK (`streamText`, consumed internally; `generateObject` when JSON output is required). The worker loads the node's input, resolves the model through `system_ai_models`, builds a system prompt, a user prompt and messages, calls the provider, persists the result, and returns token usage to the workflow for billing.

[`textGeneratorActivity`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/temporal/activities/activities.service.ts) delegates to [`TextGeneratorService.process`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/text-generator/text-generator.service.ts).

## When it runs

`textGeneratorActivity` is invoked from the [`processSingleNode`](/worker/workflows/process-single-node) workflow, which has an explicit `case NodeType.TEXT_GENERATOR` (it is not in the `UNIFORM_NODE_ACTIVITIES` map). Inside the cancellation scope the workflow first calls [`validateModelAccessActivity`](/worker/activities/validate-model-access) with `data.aiModel` and `data.aiSystem`, then the activity. Afterwards it calls [`chargeTokensActivity`](/worker/activities/charge-tokens) with the returned token counts and `webSearchCalls`. When the run is cancelled mid-stream, the activity returns a `CancelledNodeOutput` and the workflow settles the node as cancelled instead.

The proxy (`workflows/configs.ts`) uses a `startToCloseTimeout` of 30 minutes, a 2-minute heartbeat timeout, the `RETRY_ON_WORKER_LOSS` retry policy, and `WAIT_CANCELLATION_COMPLETED` cancellation. The activity runs inside `runCancellableNode`, heartbeats on every stream event, and arms a stream-stall watchdog (`STREAM_STALL_LIMIT_MS`, 5 minutes without stream progress).

## Activity signature

```typescript
async textGeneratorActivity(
  props: ExecuteNodeActivityProps,
): Promise<TextGeneratorResponse | CancelledNodeOutput>
```

`TextGeneratorResponse`:

```typescript
{
  output?: string;
  inputTokens?: number;
  outputTokens?: number;
  webSearchCalls?: number;
}
```

The activity returns only these fields; the generated text and logs are written by `TextGeneratorService.process` (see [Persisted node `data`](#persisted-node-data-highlights)). When `flowId` is set, each text chunk is also pushed to the editor through `notificationService.sendStreamChunk` (best effort; a failed emit never fails the activity).

## End-to-end flow

1. **Load node** — `fetchNodeRow` reads the run's input snapshot (`node_executions.input`) during a run, or `flows_nodes.data` when there is no `execId`.
2. **Hydrate memory** — when `memory` is on and there is a `sessionId`, read the session's stored memories from `session_state_entries` (`scopeType = 'memory'`) and merge them into `userSessionsChat`.
3. **Validate provider** — `data.aiSystem`, when set, must be one of the `AiSystems` values or `perplexity`; otherwise `UserConfigError` ("AI provider '…' is not supported.").
4. **Load model metadata** — `data.aiModel` is required ("Select a model before running this node."). `SELECT` from `system_ai_models` where `modelName` matches (`aiCompany`, `isVisionModel`, token limits, `contextWindow`, `supportsReasoning`, `reasoningAlwaysOn`, `supportsStructuredOutput`, `modelType`). A missing row fails with "The selected model is no longer available. Pick a different model." A model with `modelType = "Evaluation"` takes the TypeSafe evaluation path instead of the steps below.
5. **Instantiate model** — map `aiCompany` (lowercased) to an `AiProviderService` client: `openai`, `anthropic`, `gemini`, `perplexity`, `xai`, `groq`, `moonshot`, `mistral`, `cloudflare`. Anthropic ids are normalized through `ANTHROPIC_MODEL_MAP`. An unconfigured provider fails with "This model's provider is not configured."
6. **Build prompts** — `buildSystemPrompt` and `buildUserPrompt` (see [Prompt structure](#prompt-structure)).
7. **Extract multimodal content** — if `multimodalEnabled`, find file URLs in the prompts and memories and process them (see [Multimodal](#multimodal)).
8. **Build tools and options** — attach web search tools when `isWebEnabled`; build provider options; resolve the JSON schema when `requireJsonOutput` is on.
9. **Build messages** — filtered session memories as `ModelMessage[]`, with the user prompt and file parts added to the last user message (or a new one). With no prompt, no files and no memory, a fallback user message is sent: "Complete the task described in the system instructions."
10. **Call LLM** — `streamText` (or `generateObject` for structured output). If the provider rejects a sampling parameter as unsupported, the call is retried once without `temperature`, `topP`, `topK`, `frequencyPenalty` and `presencePenalty`.
11. **Consume the stream** — collect text, reasoning, sources, tool calls and results, and usage from the `text-delta`, `reasoning-delta`, `source`, `tool-call`, `tool-result`, `finish-step`, `finish`, `abort` and `error` events. A response with no text, no reasoning and no tokens fails with "The model returned no response. Try again." Reasoning is capped at 200,000 characters.
12. **Persist** — see [Persisted node `data`](#persisted-node-data-highlights). If persisting fails after the provider answered, the error carries the spent tokens so the workflow still charges them.
13. **Return** — `output` (`text`, falling back to the reasoning text), `inputTokens`, `outputTokens`, `webSearchCalls`.

## Prompt structure

`buildSystemPrompt` returns only the persona: `personaData` (edge items, joined with blank lines) or the `persona` field. It is passed as the system instructions when non-empty.

`buildUserPrompt` builds the user turn:

```text
<prompt>

Instructions in crafting your response: <instruction>

For the prompt mentioned above, here is the referenced content or context: <content>
```

Each part resolves from its `*Data` edge array (items deduplicated by `id` and joined with blank lines) and falls back to the plain field (`prompt`, `instruction`, `content`). Empty parts are left out. When multimodal files are found, the URLs are stripped from the prompts before they are sent.

## Persisted node `data` highlights

`persistNodeSuccess` writes to `flows_nodes.data` and the run's `node_executions.outputData`:

| Field | Role |
| ----- | ----- |
| `text` | Model output (`text`, or the reasoning text when the model returned no text) |
| `logs` | Structured execution data object (see [Logs structure](#logs-structure)) |
| `executionStatus` | `COMPLETED`, with `errorMessage` and `errorStatusCode` cleared |
| `nodeUsedTokens` | Previous value plus this run's input and output tokens |
| `userSessionsChat` | When `memory` is on and there is a prompt, the current session gains the user and assistant entries. The same two entries are appended to `session_state_entries`. `userSessionsChat` is one of the input fields the live `flows_nodes` write skips, so it lands only in `node_executions.outputData`. |

The worker does not write `previewResponses`.

## Web search

When `isWebEnabled` is true, tools are attached by the provider that `AI_COMPANY_TO_SYSTEM` maps the model's `aiCompany` to:

| Provider | Tool key | SDK call |
| -------- | -------- | -------- |
| OpenAI | `web_search` | `openai.tools.webSearch({})` |
| Anthropic | `web_search` | `anthropic.tools.webSearch_20250305({})` |
| Gemini | `enterprise_web_search` | `google.tools.googleSearch({})` |

Other providers get no tools when web search is requested. Perplexity models search on their own; `search_context_size` is passed as `web_search_options`.

### Web search billing

The service counts the tool calls named `web_search` in the run and returns the count as `webSearchCalls`. The workflow passes it to [`chargeTokensActivity`](/worker/activities/charge-tokens), and the back bills each call at the provider's web search price (`webSearchPriceKeyFor` in `back/src/app-api/product/web-search-price-key.ts`):

| Provider | Web search price key |
| -------- | -------------------- |
| OpenAI | `open-ai-web-search` |
| Anthropic | `anthropic-web-search` |
| Gemini | None — its tool is named `enterprise_web_search`, so it is not counted |

The same count is charged when the node fails after the provider answered (see [Error handling](/worker/workflows/process-single-node#error-handling)).

## Structured output

When `requireJsonOutput` is true:

- The model must have `supportsStructuredOutput = true`, or the run fails with "The selected model does not support required JSON output. Turn it off or pick a compatible model."
- The schema comes from `jsonOutputSchemaData` or `jsonOutputSchema`; empty fails with "Add a JSON schema before running with Require JSON Output on.", invalid JSON with "The JSON schema is not valid JSON. Fix it before running."
- The worker calls `generateObject` with the schema and stores the object pretty-printed (`JSON.stringify(object, null, 2)`) as `text`.
- Output that does not match the schema fails with a `SchemaValidationError` ("The model could not produce output matching the required JSON schema."), carrying the spent tokens.

## Multimodal

When `multimodalEnabled` is true, `extractMultimodalContent` finds URLs in the user prompt, the system prompt and the loaded session memories, keeps only the ones with a supported file extension, and dedupes them, up to **`MAX_URLS = 10`** per execution. Supported extensions: `jpg`, `jpeg`, `png`, `gif`, `webp`, `heic`, `heif`, `bmp`, `tiff`/`tif`, `svg`, `avif`, `pdf`. Matched URLs are stripped out of the prompt, system prompt and memory text.

Only **images and PDFs** are processed. The model must be flagged `isVisionModel = true`, or the run fails with "The selected model does not support multimodal input. Turn Multimodal off or pick a vision-capable model." The model's `aiCompany` is then mapped to a provider; a provider without an entry in `PROVIDER_LIMITS` (Perplexity, Moonshot, Cloudflare) fails with "The selected model provider does not support multimodal input."

For each URL, `processMultimodalUrls` (`multimodal-file-processor.ts`), using `SafeFetchService`:

1. **Checks the type with a `HEAD` request** — when it answers with a content type that is neither an image nor a PDF, the run fails ("Only images and PDFs are allowed.").
2. **Downloads the file** — with a 5-minute timeout and a `MAX_DOWNLOAD_BYTES = 100 MB` cap. A network error, non-2xx response or oversized file throws `UserConfigError`.
3. **Resolves its MIME type** — from the response's `Content-Type`, falling back to the file extension when the header is missing or `application/octet-stream`.
4. **Validates format and size** against the provider's allowed MIME types and per-type byte limit.
5. **Enforces per-execution image and PDF counts**, after all URLs are processed.
6. **Encodes the file** — on providers with `supportsDirectImageUrl`, images are sent as the original URL; everything else (all PDFs, and images on other providers) is base64-encoded from the downloaded bytes.

### Per-provider limits (`PROVIDER_LIMITS`)

| Provider | Max images | Max PDFs | Max image size | Max PDF size | Image MIME types | Direct image URL? |
| -------- | ---------- | -------- | -------------- | ------------ | ---------------- | ----------------- |
| OpenAI | 10 | 1 | 26 MB | 43 MB | jpeg, png, gif, webp | Yes |
| Anthropic | 100 | 5 | 5 MB | 6 MB | jpeg, png, gif, webp | No (base64) |
| Gemini | 3600 | 3600 | 26 MB | 26 MB | jpeg, png, webp, heic, heif | No (base64) |
| Groq | 1 | 0 | 5 MB | — | jpeg, png | No (base64) |
| xAI | 10 | 0 | 26 MB | — | jpeg, png | Yes |
| Mistral | 8 | 0 | 10 MB | — | jpeg, png, gif, webp | Yes |

File parts are always sent as `{ type: "file", data, mediaType }`, including images, where `data` is the URL or the base64 string and `mediaType` is the resolved MIME type. They follow a `{ type: "text", text: userPrompt }` part in the last user message; if the last message is not a user message, a new user message is added.

## Session memory

When `memory` is true and the run has a `sessionId`, the session's memories are loaded from `session_state_entries` and merged into `userSessionsChat`. `processMemoryFilter` applies one of five strategies:

| `selectedType` | Behavior |
| -------------- | -------- |
| `Load First X Entries` | First N entries (`selectedIndex`, default 5) |
| `Load Last X Entries` | Last N entries (`selectedIndex`, default 5) |
| `Load First X Words` | First N words across all memories (`selectedNumber`, default 50) |
| `Load Last X Words` | Last N words across all memories (`selectedNumber`, default 50) |
| `Load All Entries` | All memories with valid content (default, and any unknown value) |

Filtered memories become `ModelMessage[]` with their original roles (`system` memories become system messages). After generation, if there was a user prompt, a user entry and an assistant entry with timestamps are appended (see [Persisted node `data`](#persisted-node-data-highlights)).

## Provider-specific generation options

`buildProviderOptions` branches on the provider mapped from `modelInfo.aiCompany`. Max output tokens are only sent when `autoToken` is explicitly `false` and the configured value is a positive number; otherwise the provider's default applies.

- **Anthropic** — `anthropicToken`. Thinking is on when the model supports reasoning and either `reasoningAlwaysOn` is set or `reasoning` is not `false`. Adaptive-thinking models (Claude 4.6+ and 5 families) get `thinking: { type: "adaptive" }` with `effort` from `aiEffort`; older models get `thinking: { type: "enabled", budgetTokens }` at 80% of max output (at least 1,024). Without reasoning support: `anthropicTemperature`, `anthropicTopP`, `anthropicTopK`.
- **Gemini** — `geminiMaxOutputTokens`; `temperature`, `topP`, `topK` unless reasoning is active.
- **OpenAI** — `aiTokens`. With reasoning: `providerOptions.openai.reasoningEffort` from `aiEffort`. Without: `aiTemperature`, `aiPp` → `presencePenalty`, `aiFp` → `frequencyPenalty` (and `reasoningEffort` when `aiEffort` is set).
- **Perplexity** — `max_tokens`/`perplexityTokens`, `perplexityTemperature`, `perplexityTopP`, `perplexityTopK`; `search_context_size` as `web_search_options`; `reasoning_effort` on reasoning models.
- **xAI** — `aiTokens`, `aiTemperature`; `reasoningEffort` on reasoning models (`grok-3-mini` accepts only low/high).
- **Mistral** — `aiTokens`, `aiTemperature`; `reasoningEffort` `high` or `none` on reasoning models.
- **Moonshot** — `aiTokens`; `reasoningEffort` for `kimi-k3` models, or `thinking` enabled/disabled on other reasoning models (`kimi-k2.7` is always on).
- **Groq** — `groqMaxTokens`; `groqTemperature`/`groqTopP` (falling back to `geminiTemp`/`geminiTopP`) unless reasoning; `seed`; `groqStop` as stop sequences; `reasoningEffort` for `gpt-oss`, `qwen-qwq` and `deepseek-r1` models.
- **Other providers** (Cloudflare) — `aiTokens` or `geminiMaxOutputTokens`, `aiTemperature`.

Reasoning is active when `modelInfo.supportsReasoning` is true and either `reasoning` is true or `modelInfo.reasoningAlwaysOn` is true. Effort values outside low/medium/high fall back to `low`.

### Model and provider fields

The model always comes from `data.aiModel`; the provider client comes from the model's `aiCompany` in `system_ai_models`. `data.aiSystem` is only validated and passed to model-access checks and billing. The `AiSystems` values are `openai`, `anthropic`, `gemini`, `groq`, `perplexityai`, `xai`, `moonshot`, `mistral`, `typesafe`, `cloudflare`.

## Provider errors

`translateProviderError` maps provider failures to the [error taxonomy](/worker/error-taxonomy):

| Condition | Error | userMessage |
| --- | --- | --- |
| Context window exceeded | `ContextLengthError` | The prompt is too long for this model's context window. |
| Rate limit (HTTP 429) | `ProviderError`, retryable | The model is rate-limited. Try again in a moment. |
| Provider overloaded | `ProviderError`, retryable, 529 | The model provider is overloaded. Try again shortly. |
| Content filter or refusal | `ProviderError` | The model refused this prompt. |
| Other token-limit message | `UserConfigError` | The prompt is too long for this model. |
| Network, fetch or timeout | `IntegrationError` | The model provider is unreachable. Try again. |
| Anything else | `ProviderError` | The model returned an error. Try again. |

Errors raised after the stream started carry the tokens spent so far, so the workflow can charge them.
