## Overview

The **image generator** node produces an image from a prompt assembled out of several node fields, then uploads the result and charges the user for one (or more) generated images. The node supports six provider systems, selected by `nodeData.aiSystem` (default `openai`):

- **`openai`**, **`gemini`**, **`fal`** — call [`generateImage()`](https://ai-sdk.dev/docs/ai-sdk-core/image-generation) from the [AI SDK](https://ai-sdk.dev/) against a model returned by `aiProviders.<provider>.image(...)`.
- **`stabilityai`**, **`ideogram`**, **`opensources`** (Kandinsky via Replicate) — make direct HTTP calls, bypassing the AI SDK entirely.

[`imageGeneratorActivity`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/temporal/activities/activities.service.ts) delegates to [`ImageGeneratorService.process`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/image-generator.service.ts), which dispatches through two lookup tables keyed by `aiSystem`: `PROVIDER_BUILDERS` (the AI SDK path) and `DIRECT_HTTP_BUILDERS` (the direct-HTTP path). If `aiSystem` matches neither, the activity throws a `UserConfigError`.

<Note>
  This node was ported from the back's `imageGeneratorNode` handler. See [Provenance](#provenance) for the full source-to-worker file mapping and the behavior differences introduced during the port.
</Note>

## When it runs

`imageGeneratorActivity` is invoked from the [`processSingleNode`](/worker/workflows/process-single-node) workflow when the node type is **image generator** (`NodeType.IMAGE_GENERATOR`, stored value `imageGenerator`).

## Activity signature

```typescript
async imageGeneratorActivity({
  execId: string,
  nodeId: string,
  sessionId: string,
  userId: string,
  flowId: string,
  flowVersionHistoryId: string | null,
}): Promise<ImageGeneratorResponse>
```

`ImageGeneratorResponse`:

```typescript
{
  text: string; // the stored image URL
}
```

## End-to-end flow

1. **Load node** — read the node row (`execId`-scoped `node_executions.input` during a run, `flows_nodes.data` otherwise); read `data`.
2. **Resolve the provider** — look up `nodeData.aiSystem` (default `"openai"`) in `PROVIDER_BUILDERS` and `DIRECT_HTTP_BUILDERS`. Neither match throws `UserConfigError`.
3. **Build the prompt** — assemble `prompt`/`subject`/`environment`/`tone`/`view`/`style`/`negativePrompt` (see [Building the prompt](#building-the-prompt)). An empty result throws `UserConfigError`.
4. **Heartbeat `"generating"`** — `Context.current().heartbeat({ nodeId, phase: "generating" })`.
5. **Generate** — either `generateImage()` from the `ai` package (AI SDK path) or the provider's own HTTP call chain (direct-HTTP path).
6. **Heartbeat `"uploading"`** — `Context.current().heartbeat({ nodeId, phase: "uploading" })`.
7. **Upload** — `POST /worker/store-image` with the generated bytes or source URL (see [Storing the image](#storing-the-image)).
8. **Charge** — `POST /worker/charge-tokens` (see [Billing](#billing)). On the direct-HTTP path, the provider module charges itself, at its own point in the call chain, instead of `process()` charging once afterward.
9. **Persist** — write `text`, `previewIndex`, and `previewResponses` back onto the node's `data` (see [Persisted node `data`](#persisted-node-data)), with `executionStatus: "COMPLETED"`.
10. **Return** — `{ text: src }`.

## Node `data` fields

### Shared prompt fields

Read by [`buildPrompt`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/build-prompt.ts), independent of provider:

| Field | Role |
| ----- | ---- |
| `prompt` | Main prompt text. |
| `subject` | Subject line, appended as `Subject: …`. |
| `environment` | Appended as `Environment: …`. |
| `tone` | Appended as `Tone: …`. |
| `view` | Appended as `View: …`. |
| `style` | Appended as `Style: …`, but only when `style_present === "None"`. |
| `negativePrompt` | Read by several direct-HTTP providers as a separate negative-prompt parameter; not merged into the assembled prompt text itself. |

Each of these fields also has an edge-driven counterpart — `promptData`, `subjectData`, etc. When the corresponding `*Data` array is non-empty, its items' `text` values (joined with `" \n"`) override the static field before the prompt is assembled.

### Provider selection

| Field | Role |
| ----- | ---- |
| `aiSystem` | Selects the provider system: `openai` (default), `gemini`, `fal`, `stabilityai`, `ideogram`, or `opensources`. |
| `aiModel` | Model id, read by `openai`, `gemini`, and (via [`resolveImageModel`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/providers/resolve-image-model.ts)) `stabilityai`/`ideogram` as the primary source of the model — the per-provider legacy field (`engineId`, `ideogramModel`) is a fallback for stored data older than `aiModel`. |
| `spaceId` | Optional; threaded through to the upload call. |

### `openai`

| Field | Role |
| ----- | ---- |
| `size` | Passed straight through to `generateImage()`. |
| `quality` | When set, forwarded as `providerOptions.openai.quality`. |

The actual API call always targets `gpt-image-1` — `aiModel` is not read for the call itself. It is only used, via `persistModel`, to label the stored image (see [Persisted node data](#persisted-node-data)).

### `gemini`

| Field | Role |
| ----- | ---- |
| `aiModel` | Model id; falls back to a literal `"gpt-image-1"` default if unset (a ported default, not a real Gemini id — no observed node hits this fallback in practice). |
| `aspectRatio` | Passed to `generateImage()`'s standard `aspectRatio` parameter, which the AI SDK's Google adapter maps onto the real `imageConfig.aspectRatio`. No default is forced when unset. |

### `fal`

| Field | Role |
| ----- | ---- |
| `falModel` | Selects the model family: any `"…pro…"` variant, `"schnell"`, `"dev"`, or a Flux id looked up in the model maps. Defaults to `"pro"`. |
| `imageSize` | Fal's named size preset (e.g. `landscape_4_3`); sent via `providerOptions.fal.image_size` as a raw passthrough, not the SDK's own `size`/`aspectRatio` params. |
| `sync_mode` | Compared against the **literal string** `"false"` — only that exact string resolves to `false`; anything else, including the boolean `false` and `undefined`, resolves to `true`. Preserved as a known back bug rather than normalized. |
| `num_images` | Sent as `n`. Defaults to `1`. |
| `fal_seed` | Sent as `seed`. |
| `guidance_scalefloat` | Sent as `providerOptions.fal.guidanceScale` for pro/dev/Flux families (not `schnell`). Defaults to `3.5`. |
| `safety_tolerance` | Sent as `providerOptions.fal.safetyTolerance` for pro/Flux families only (not `schnell` or `dev`). Defaults to `"2"`. |
| `inference_steps` | Sent as `providerOptions.fal.numInferenceSteps`, capped at `12` for `schnell` and forced to `8` for "fast" Flux variants (`flash`/`turbo` in the id). |

### `stabilityai`

Dispatch is three levels deep: `type` picks the operation family, then `engineId` (Text to image) or `imageToImageSelectedType` (Image to image) picks the specific method.

| Field | Role |
| ----- | ---- |
| `type` | `"Text to Image"` (default), `"Image to image"`, `"Enhance resolution"`, or `"Upscale Image"`. Any other value throws `UserConfigError`. |
| `engineId` | Resolved via `resolveImageModel` (falls back to legacy field, default `"sd3"`). Selects between the SD3 family, `core`, `stability-ultra`, or the legacy text-to-image engine. |
| `imageToImageSelectedType` | For `"Image to image"`: `"sketch"` (default), `"structure"`, or `"style"`. |
| `inputPreview` | Required for `"Image to image"` — missing it throws `UserConfigError`. Also read by `"Enhance resolution"`/`"Upscale Image"`. |
| `output_format`, `aspect_ratio`, `steps`, `cfg_scale`, `height`, `width`, `clip_guidance_preset`, `promptWeight`, `style_present` | Per-method request parameters for the text-to-image family. |
| `influenceStrength`, `outputFormat`, `seed`, `selectedImageToImageAspectRatio` | Per-method request parameters for the image-to-image family (note `outputFormat`, camelCase, is a distinct field from `output_format`). |

`"Enhance resolution"` and `"Upscale Image"` both route to the same upscale method — the back's original code only recognized `"Upscale Image"`, which meant every real `"Enhance resolution"` node silently no-op'd. Accepting both is a deliberate fix (see [Provenance](#provenance), D16).

### `ideogram`

| Field | Role |
| ----- | ---- |
| `type` | `"Image to image"` routes to remix (requires `inputPreview`); anything else routes to generate. `"Expand Image"` is explicitly refused — see below. |
| `ideogramModel` | Model id, e.g. `ideogram-v3`, `ideogram-v3-turbo`, `ideogram-v3-quality`. Also drives the rendering speed sent to the API. |
| `magicPrompt` | Sent as `magic_prompt`. |
| `aspect_ratio_ideogram` | Sent as `aspect_ratio`. Mutually exclusive with `resolution` — if both are set, `resolution` is dropped before the request is sent. |
| `resolution` | Sent as `resolution`, subject to the mutual-exclusion rule above. |
| `style_type`, `negativePrompt` | Additional request parameters. |
| `inputPreview` | Required for remix; the source image is fetched and embedded in the request. |

`type: "Expand Image"` throws `UserConfigError`. The back silently routed this to its upscale method; this port refuses instead, since no real node was found using this combination — see [Provenance](#provenance), D15.

### `opensources` (Kandinsky via Replicate)

| Field | Role |
| ----- | ---- |
| `steps` | Number of inference steps. Defaults to `75`. |
| `width`, `height` | Image dimensions. Default to `1024` each. |
| `negativePrompt` | Sent as a top-level `negative_prompt` sibling of the Replicate `input` object (a confirmed-dead field in Replicate's real API, preserved as-is). |

There is no model selector for this provider system — `opensources` maps unconditionally to the Kandinsky 2.2 model on Replicate.

## Building the prompt

[`buildPrompt`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/build-prompt.ts) runs in two steps:

1. **Edge overrides** — for each of `prompt`, `subject`, `environment`, `tone`, `view`, `style`, and `negativePrompt`, if the matching `<field>Data` array is non-empty, its items' `text` values are joined with `" \n"` and replace the static field.
2. **Merge** — the resolved fields are concatenated into a single string in a fixed order (`Prompt:`, then `Style:` only when `style_present === "None"`, then `View:`, `Subject:`, `Environment:`, `Tone:`), each on its own line.

An empty result (no text at all) throws `UserConfigError` before any provider call is attempted.

## Storing the image

Uploads go through `storeGeneratedImage` (in [`store-and-charge.ts`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/store-and-charge.ts)), which calls `POST /worker/store-image`:

```typescript
// request
{
  nodeId: string;
  execId: string;
  provider: string;   // e.g. 'openAi', 'gemini', 'fal', 'stabilityAi', 'ideogram', 'openSources'
  model: string;
  userId: string;
  flowId?: string;
  spaceId?: string;
  mimeType?: string;
} & (
  | { base64: string; sourceUrl?: never }
  | { sourceUrl: string; base64?: never }
)

// response
{ success: true, src: string }
```

Exactly one of `base64` (raw bytes for providers that return generated bytes directly) or `sourceUrl` (a provider-hosted URL to fetch and re-upload) is sent. A non-2xx response or a response without `success: true` throws `SystemError`.

<Info>
  `/worker/store-image` is a **new** endpoint, separate from `/worker/store-payload` (used to persist other large node outputs). `/worker/store-payload` is a private claim-check: it writes to a private S3 location keyed by `(execId, nodeId)` and hands back an opaque key the worker resolves later. A generated image needs a public, durable URL that gets written into the node's `data` for the front to render — a different lifetime and a different bucket policy than a claim-check. `/worker/store-image` exists because reusing `/worker/store-payload` for this would have been the wrong contract, not a smaller one.
</Info>

## Billing

Charging goes through `chargeImageGeneration` (also in `store-and-charge.ts`), which calls `POST /worker/charge-tokens` — the same endpoint documented in [Charge tokens](/worker/activities/charge-tokens), extended with three optional fields (`label`, `usedTokens`, `billingFlowId`) that existing callers don't send.

By default, this node charges **one `usedTokens` credit per generated image** (`usedTokens: params.usedTokens ?? 1`, `label: "Image"`). Some direct-HTTP providers pass a different value instead of the default — for example, Stability's `textToImage` charges `Math.ceil(steps / 30)` credits when `steps > 30` (otherwise `1`). On the AI SDK path, `process()` charges once, after the call succeeds; on the direct-HTTP path, each provider method calls `ctx.charge(...)` itself, at whatever point in its own call chain matches the back's original charge-before-vs-after-the-call timing for that method.

<Warning>
  The back's real `openai` path charges input and output tokens separately, via two `updateTokens` calls. This endpoint's charge-deduplication logic (keyed by `(execId, nodeId)`) makes a second charge call for the same node execution a silent no-op, so that two-call behavior could not be replicated here. This is a known, tracked gap in the port — not a bug introduced by it.
</Warning>

## Persisted node `data`

### On success

| Field | Role |
| ----- | ---- |
| `text` | The stored image URL returned by `/worker/store-image`. |
| `previewIndex` | Index of the new entry within `previewResponses` (equal to the array's previous length). |
| `previewResponses` | Existing entries plus one new entry — see the shape split below. |
| `executionStatus` | `"COMPLETED"`. |
| `errorMessage` / `errorStatusCode` | Cleared to `null`. |

Other `data` fields are preserved via spread (`...nodeData`).

**`previewResponses` entry shape** — this varies by provider, and the three shapes are not interchangeable:

| Providers | Shape |
| --------- | ----- |
| `fal`, `opensources`, `stabilityai` | A bare **string** — the image URL itself. |
| `openai`, `gemini` | An **object**: `{ message: string; usedTokens: number; cost: number }` — `message` holds the URL. |
| `ideogram` | An **object**: `{ image: string; usedTokens: number; cost: number }` — note the key is `image`, not `message`. |

### On failure

The activity does not write an error field onto `data` — it **throws** a typed `NodeError` subclass instead (see [Errors](#errors)). This differs from some older, not-yet-migrated node types, which write `errorMessage`/`errorStatusCode` onto `data` without throwing and rely on a separate detection step downstream. The thrown error flows through the standard Temporal failure path shared by every migrated node type, which the front already renders correctly off `executionStatus`/`executionError` from the socket status broadcast.

## Retry and timeout behavior

`imageGeneratorActivity` is registered with `startToCloseTimeout: "5 minutes"` and `heartbeatTimeout: "30 seconds"`, and `maximumAttempts: 1` (no Temporal-level retry) in [`configs.ts`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/temporal/workflows/configs.ts). These are not measured p95 values — there is no real timing data for image generation yet — they match this codebase's existing default for a single external-provider-call activity (the same values used by `apiCallerActivity`, `thirdPartyIntegrationActivity`, and `mcpActivity`).

The service calls `Context.current().heartbeat()` twice per run, to keep the activity alive during long external calls:

- `{ nodeId, phase: "generating" }` — before the provider call.
- `{ nodeId, phase: "uploading" }` — before the upload to `/worker/store-image`.

The `opensources` (Kandinsky) provider additionally polls Replicate for prediction status, with a worker-side cap of **120 attempts at a 1-second interval (~2 minutes)**. Exceeding the cap throws `TimeoutError`. The underlying Replicate SDK/API has no such bound on its own — this poll budget is a deliberate worker-side addition, required so a stuck prediction eventually surfaces as a timeout instead of running indefinitely.

## Errors

| Condition | Class |
| --------- | ----- |
| Missing prompt, unsupported provider/mode pair, Ideogram `'Expand Image'` | `UserConfigError` |
| Missing/invalid provider API key, no user product found | `IntegrationError` |
| Provider 4xx/5xx, content-policy refusal, no image generated | `ProviderError` |
| Provider poll exceeds budget | `TimeoutError` |
| Image upload or DB write failure | `SystemError` |

Implemented by [`ai-sdk-error-classifier.ts`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/ai-sdk-error-classifier.ts) for the AI SDK path (`openai`/`gemini`/`fal`) and [`http-error-classifier.ts`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/http-error-classifier.ts) for the direct-HTTP path (`stabilityai`/`ideogram`/`opensources`).

## Provenance

This node was copy-ported from the back's `imageGeneratorNode` handler, targeting byte-identical behavior including pre-existing back bugs, with a small number of deliberate, explicitly-classified deviations. See [`PORTED_FROM.md`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/image-generator/PORTED_FROM.md) for the full source-SHA-per-file table. The deviations worth knowing about:

- **D15** — Ideogram's `'Expand Image'` mode now refuses (`UserConfigError`) instead of silently routing into the upscale method, which is what the back did.
- **D16** — Stability's upscale mode now accepts both `'Enhance resolution'` and `'Upscale Image'` labels. The back only recognized `'Upscale Image'`, so every real `'Enhance resolution'` node was a silent no-op in production; this fixes that outage rather than porting it.
- **D17** — Gemini's aspect ratio is now passed as a real `generateImage()` parameter instead of being appended to the prompt text, which is what the back did.
