</Note>

## Overview

The **API caller** node performs HTTP requests configured on the node row, with optional **polling** and **output filtering**. The Worker resolves the URL and credentials (preferring **edge-linked** values when present), merges query parameters into the URL, builds headers and body from `contentType` and related fields, executes the request through an [undici](https://undici.nodejs.org/) `Agent` from `SafeFetchService.getDispatcher` (egress policy plus optional TLS verification control), then optionally polls for a desired condition and filters the response before storing and returning the result.

[`apiCallerActivity`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/temporal/activities/activities.service.ts) delegates to [`ApiCallerService.process`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/api-caller/api-caller.service.ts).

## When it runs

`apiCallerActivity` is invoked from the [`processSingleNode`](/worker/workflows/process-single-node) workflow when the node type is **API caller** (`NodeType.API_CALLER`, stored value `apiCaller`), through the `UNIFORM_NODE_ACTIVITIES` map in `workflows/node-activities.ts`. Its proxy has a `startToCloseTimeout` of 5 minutes, a 30-second heartbeat timeout, a single attempt, and `WAIT_CANCELLATION_COMPLETED` cancellation. The activity runs inside `runCancellableNode`, which heartbeats every 3 seconds and aborts the in-flight request when the run is cancelled.

## Activity signature

```typescript
async apiCallerActivity(
  props: ExecuteNodeActivityProps,
): Promise<ApiCallerResponse | CancelledNodeOutput>
```

`ApiCallerResponse`:

```typescript
{
  result: string; // filtered or raw response body as text
}
```

The returned string is the **filtered** output when an output filter is configured and the response schema matches; otherwise it is the raw response body. When it is larger than `APICALLER_MAX_RESULT_BYTES` (default 1,000,000 bytes), the activity returns only its first 100,000 characters plus a truncation marker; the full output is still persisted (and offloaded to the claim-check store above 256 KB) for downstream nodes.

## Resolving URL and secrets (edge vs static)

Some fields can come either from **static** properties on `data` or from an edge-driven array (when the UI passes dynamic inputs):

| Concept | Static field | Edge-driven (takes precedence when non-empty) |
| ------- | ------------ | --------------------------------------------- |
| Request URL | `url` | `urlData` |
| Custom headers (JSON) | `jsonAuth` | `jsonAuthData` |
| Request body (JSON) | `jsonRequestBody` | `jsonRequestBodyData` |
| Basic auth username | `username` | `usernameData` |
| Basic auth password | `password` | `passwordData` |

Resolution rule (`resolveEdgeData`): if the `*Data` array has entries, drop duplicate items by `id`, then concatenate the non-empty `text` values with no separator; if that gives a non-empty string, use it, otherwise use the static field. After resolution, **`url` is required** — if still missing, the service throws a `UserConfigError`: `URL is required.`

## Node `data` fields

Types reference: [`ApiCallerNodeData`](https://github.com/enhancedai-com/Flux-Prompt-Worker/blob/main/src/modules/nodes/api-caller/api-caller.type.ts).

### Request line

| Field | Role |
| ----- | ---- |
| `method` | HTTP method: `GET`, `POST`, `PUT`, `DELETE`, or `PATCH`. |
| `url` | Base URL string (used if `urlData` is absent or empty). |
| `urlData` | Optional `EdgeDataItem[]` (`{ id, text, label }`); its joined `text` overrides `url` when non-empty. |
| `queryParams` | Optional `{ key, value }[]`. Each pair is set on the URL with `searchParams.set` (pairs with an empty `key` or an `undefined` `value` are skipped). |
| `requestTimeoutMs` | Optional per-request timeout. Default: **30,000 ms**. |

### Headers and auth

| Field | Role |
| ----- | ---- |
| `jsonAuth` | String containing **JSON** of header key/value pairs (e.g. `{"Authorization":"Bearer …"}`), or JSON text that parses to a string of `Name: Value` lines. Merged into the request headers. See [Errors](#errors) for the parse failures. |
| `jsonAuthData` | Optional edge override for `jsonAuth`. |
| `username` | If set, triggers **HTTP Basic** auth: `Authorization: Basic base64(username:password)`. Password defaults to empty string when omitted. |
| `password` | Used with Basic auth when `username` is set. |
| `passwordData` / `usernameData` | Optional edge overrides for `password` / `username`. |

If both `jsonAuth` (custom headers) and Basic auth apply, Basic sets `Authorization` **after** the JSON merge, so Basic **wins** for `Authorization` when both are present.

| Field | Role |
| ----- | ---- |
| `contentType` | Optional: `application/json` or `application/x-www-form-urlencoded`. When set, becomes `Content-Type` on the request. Also drives how the body is built (see [Request body](#request-body)). When a body is sent and no `Content-Type` header is set by either source, the worker sends `application/json`. |

### Request body

| Field | Role |
| ----- | ---- |
| `jsonRequestBody` | String. Interpretation depends on `contentType` (and effective content type — see below). |
| `jsonRequestBodyData` | Optional edge override for `jsonRequestBody`. |
| `formDataParams` | `{ key, value }[]` for `application/x-www-form-urlencoded` bodies. |

**Effective content type** for body building is `nodeData.contentType ?? headers['Content-Type']` (headers already include `jsonAuth` and possibly `Content-Type` from `contentType`).

Behavior of `buildRequestBody`:

- **`application/x-www-form-urlencoded`**
  - If `formDataParams` has entries: build `URLSearchParams` from key/value pairs (skip entries with missing `key` or `undefined` value).
  - Else if `jsonRequestBody` is set: parse it strictly as JSON into an object, then append each key with `String(value)` into `URLSearchParams`.
- **Other content types (including `application/json`)**
  - If `jsonRequestBody` is set: parse it with strict `JSON.parse` (`parseJsonStrict`) and send it re-serialized. There is no tolerant fallback; invalid JSON fails with `Request body is not valid JSON.`

If no body applies, the request is sent **without** a body (`undefined`). A body with `GET`, `HEAD`, or no method (which defaults to `GET`) fails the run (see [Errors](#errors)).

### TLS

| Field | Role |
| ----- | ---- |
| `validateCertificate` | Boolean; default **`true`** if omitted. When `false`, the dispatcher's connector uses `rejectUnauthorized: false` (allows self-signed or mismatched certificates). |

### Egress and response handling

- The dispatcher resolves each host through the egress policy (`modules/egress/egress-policy.ts`). A host that does not resolve, or resolves to a denied address range, fails with a non-retryable `BlockedAddressError` (`Request blocked by egress policy: …`).
- Redirects are not followed (`redirect: "manual"`). A 3xx response fails with `RedirectRefusedError`: `Request blocked: redirect responses are not followed. …`
- A response whose `content-type` is an image, video, audio, PDF or `application/octet-stream` is returned as a `data:<type>;base64,…` URI. Text responses have NUL characters stripped.

### Polling

| Field | Role |
| ----- | ---- |
| `pollingEnabled` | Boolean. When `true`, enables the polling pipeline after the initial request. |
| `pollingInterval` | Seconds between retry attempts. Default: **5**. |
| `pollingRetryDuration` | Total timeout in seconds for all polling attempts. Default: **60**. |
| `pollingConditionField` | JSON field path (dot-separated, e.g. `status.state`) to check on each response. When set with `pollingConditionMatch`, uses **condition-based** polling. |
| `pollingConditionMatch` | Regex pattern matched against the extracted field value. Polling continues **while** the field matches; stops when the field no longer matches or is absent. |
| `pollingCallCount` | Written by the Worker: total number of HTTP requests made (1 initial + polling attempts). |

The polling strategy is chosen automatically:

- **Status-based**: When `pollingConditionField` or `pollingConditionMatch` are empty. Retries until the HTTP status is 2xx or the timeout expires.
- **Condition-based**: When both fields are set. Retries while the extracted JSON field matches the regex pattern; stops when it no longer matches.

The activity [heartbeats](https://docs.temporal.io/develop/typescript/activity-heartbeats) with `{ phase: "polling" }` before each polling retry, on top of the 3-second keep-alive heartbeat from `runCancellableNode`. The number of retries is `floor(pollingRetryDuration / pollingInterval)`.

### Output filtering

| Field | Role |
| ----- | ---- |
| `outputFilter` | Optional `OutputFilterConfig` with `selectedPaths`, `mode`, and `schemaHash`. |
| `filteredText` | Stores the output after filtering (separate from raw `text`). |

`OutputFilterConfig`:

```typescript
{
  selectedPaths: string[];       // JSON paths to extract
  mode: 'structured' | 'raw';   // output format
  schemaHash: string;            // base64 hash of response structure
}
```

**Schema validation**: Before applying the filter, the Worker computes a hash of the current response structure and compares it to `schemaHash`. If they differ (response structure changed), the filter is cleared and the raw response is returned instead.

**Filter modes**:

- **Structured** — Returns a JSON object preserving only the selected paths with their nested structure.
- **Raw** — Returns the selected leaf values as newline-separated plain text.

Both modes support array-root responses by iterating each item and applying filters per element.

## End-to-end flow

1. Load the node with `fetchNodeRow` (the run's `node_executions.input` during a run, `flows_nodes.data` otherwise) and cast `data` to `ApiCallerNodeData`. Resolve the user's company id for the egress log.
2. Resolve URL, auth, and body fields (edge vs static).
3. Construct `URL`, apply `queryParams` via `searchParams.set`.
4. Build `RequestInit`: method, headers, body, and the egress-policy `dispatcher` with TLS options.
5. Execute the initial `fetch(url, options)` with `redirect: "manual"` and the request timeout.
6. **If polling is enabled**, delegate to the polling pipeline (status-based or condition-based). On timeout, throw a `TimeoutError`.
7. **If polling is disabled** and the status is outside 2xx, throw (4xx → `UserConfigError`, otherwise `IntegrationError`).
8. Apply output filter if configured (with schema hash validation).
9. `persistNodeSuccess`: merge the resolved data with `text` (raw response), `filteredText` (filtered output if applicable), `executionStatus: 'COMPLETED'`, and cleared error fields into `flows_nodes.data` and the run's `node_executions.outputData`.
10. Return `{ result: outputText }`.

## Persisted node `data`

### On success

| Field | Role |
| ----- | ---- |
| `text` | Raw response body as a **string**. |
| `filteredText` | Filtered output string when output filter is applied and schema matches. |
| `outputFilter` | Preserved or cleared (set to `null` if schema changed). |
| `pollingCallCount` | Total HTTP requests made (initial + retries). |
| `executionStatus` | `'COMPLETED'`. |
| `errorMessage` | `null`. |
| `errorStatusCode` | `null`. |

### On failure

`ApiCallerService` writes nothing on failure. The `processSingleNode` workflow's failure path calls [`generateExecutionLogsActivity`](/worker/activities/generate-execution-logs), which marks the run's `node_executions` row `isError = true` with the error as its `output`, and merges into `flows_nodes.data`:

| Field | Role |
| ----- | ---- |
| `errorMessage` | `<userMessage> — <devMessage>` (or just one of them when they are equal or one is missing). |
| `text` | Cleared to `""` so a stale response is not shown. |
| `response` | Cleared to `null`. |
| `jsonRequestBody` | Cleared to `""` when the body was fed by an edge (`jsonRequestBodyData` non-empty). |

## Errors

All are structured errors (`UserConfigError` unless noted) with a real `userMessage`:

| Cause | userMessage |
| ----- | ----- |
| Missing node | `This node no longer exists. Refresh the page.` (`NodeNotFoundError`) |
| Missing URL after resolution | `URL is required.` (`requireField`) |
| URL fails to parse | `URL is malformed.` |
| GET/HEAD configured with a request body (`BODYLESS_METHODS`) | `The <METHOD> method cannot send a request body. Select POST, PUT or PATCH, or remove the request body.` |
| `jsonAuth` is not valid JSON | `Authentication headers field is not valid JSON.` |
| `jsonAuth` parses to something other than an object or a header string (e.g. an array or a number) | `Authentication headers must be a JSON object or a header string.` — note `jsonAuth` accepts either a JSON object of headers directly, or JSON text that parses to a **string**, which is then read as raw `Name: Value` header lines |
| A header line in that raw-string form has no `:` separator | `Authentication header is missing a ':' separator.` |
| A header line has an empty name before the `:` | `Authentication header has an empty name.` |
| `jsonRequestBody` is not valid JSON (JSON content type, or the form-urlencoded fallback which also parses it as JSON before re-encoding as form params) | `Request body is not valid JSON.` (field `jsonRequestBody`) — the same message either way |
| HTTP 4xx response | `The remote server rejected the request (HTTP <status>)<: reason>` (`UserConfigError`) |
| HTTP response outside 2xx and not 4xx (e.g. 5xx) | `The remote server failed (HTTP <status>)<: reason>. Try again.` (`IntegrationError`) |
| Polling exhausts its retry duration without a match | `Polling did not match '<pollingConditionField>' within <N>s.` (`TimeoutError`) |
| Request exceeds `requestTimeoutMs` | `The remote server did not respond in time. Try again.` (`TimeoutError`) |
| Network failure | `The remote server did not respond. Try again.` (`IntegrationError`) |
| Host blocked by the egress policy, or a redirect response | `Request blocked …` (`BlockedAddressError` / `RedirectRefusedError`) |
| Output filter set but the response is not JSON | `The response is not valid JSON, so the filter could not be applied.` (`IntegrationError`) |
| Output filter fails while applying | `The response filter could not be applied.` (`IntegrationError`) |

`<reason>`, when present, is a short excerpt pulled from the response body's `error`/`message`/`userMessage`/`detail` field (or the raw body text), capped at 300 characters.
