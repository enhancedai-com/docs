title: "Variáveis de Ambiente"

27 env vars no `worker/.env.example`, validadas via Zod em `src/env.ts`. Legenda: **Obrigatória** = a app quebra ou uma feature falha silenciosamente sem ela, **Opcional** = tem default/fallback no código.

| Var | Obrigatória? | Propósito |
|---|---|---|
| TEMPORAL_ADDRESS | Opcional | endereço do Temporal server (default localhost:7233) |
| TEMPORAL_TASK_QUEUE | Opcional | nome da task queue (default enhanced-ai-queue) |
| TYPEORM_HOST | Obrigatória | host do Postgres |
| TYPEORM_PORT | Obrigatória | porta do Postgres |
| TYPEORM_USERNAME | Obrigatória | usuário do Postgres |
| TYPEORM_PASSWORD | Obrigatória | senha do Postgres |
| TYPEORM_DATABASE | Obrigatória | nome do banco Postgres |
| REDIS_HOST | Obrigatória | host do Redis (pub/sub de notificações de status) |
| REDIS_PORT | Obrigatória | porta do Redis |
| OPENAI_API_KEY | Obrigatória | cliente OpenAI |
| ANTHROPIC_API_KEY | Obrigatória | cliente Anthropic |
| GENAI_API_KEY | Obrigatória | cliente Google GenAI |
| GROQ_API_KEY | Obrigatória | cliente Groq |
| PPLX_API_KEY | Obrigatória | cliente Perplexity |
| XAI_API_KEY | Obrigatória | cliente xAI |
| SEARCH_API_KEY | Obrigatória | busca web (node audio-transcriber) |
| AWS_ACCESS_KEY_ID | Opcional | credenciais Lambda (node de scripting) |
| AWS_SECRET_ACCESS_KEY | Opcional | credenciais Lambda |
| AWS_REGION | Opcional | região AWS (lida implicitamente pelo SDK) |
| LAMBDA_ENDPOINT | Opcional | endpoint custom do Lambda (LocalStack/dev) |
| LAMBDA_PYTHON_ALIAS | Obrigatória | alias do Lambda `code-executor-python` (`non-prod`/`prod`) invocado como `Qualifier`, pra dev/staging/prod baterem em aliases isolados da mesma função — sem default, falha fechado se não definida |
| URL_MAIN_API | Obrigatória | URL base do `back` para chamadas internas |
| INTERNAL_API_KEY | Obrigatória | auth das chamadas internas ao `back` |
| INTEGRATIONS_ENCRYPTION_KEY | Obrigatória | descriptografa credenciais de `user_integrations` (adapter Stripe) — precisa bater com o valor do `back` |
| CLAIM_CHECK_THRESHOLD_BYTES | Opcional | limiar do padrão claim-check (default 262144) |
| APICALLER_MAX_RESULT_BYTES | Opcional | limite de tamanho do resultado no node api-caller (default 1_000_000) |
| LOG_PROVIDER_OPTIONS | Opcional | flag de debug, loga opções do provider de IA |

Todas as 27 vars estão em uso ativo — nenhuma obsoleta. `LAMBDA_ENDPOINT`, `CLAIM_CHECK_THRESHOLD_BYTES`, `APICALLER_MAX_RESULT_BYTES` e `LOG_PROVIDER_OPTIONS` são lidas direto via `process.env`, fora do schema Zod — sem type-safety aí, mas é esperado já que todas são opcionais com fallback.

## Pegadinha cross-repo

`INTEGRATIONS_ENCRYPTION_KEY` precisa ser **idêntica** ao valor do `back` — mesmo parâmetro SSM em todo ambiente, e nunca pode ser `JWT_SECRET`. A cópia do helper de descriptografia de credenciais no worker (portada de `back/src/common/credentials-encryption.service.ts` pra migração P0+Stripe, `868ke6j3r`) propositalmente não tem fallback pro `JWT_SECRET`: uma linha de `user_integrations` criptografada pelo `back` só descriptografa no worker se as chaves baterem exatamente.

## CI/CD

As vars de runtime não são injetadas na imagem Docker em tempo de build/CI — elas vivem na task definition do ECS (respaldada por SSM), buscada fresh a cada deploy. O workflow do GitHub Actions em si só precisa de 2 secrets do repo: `AWS_ACCESS_KEY_ID` e `AWS_SECRET_ACCESS_KEY`, ambos confirmados presentes.
