## Overview

`processAgent` was meant to execute a complete agent: every node of a flow, in dependency order. It was never finished, and the worker does not run it today.

## Status

<Warning>
`processAgent` is **not registered** with the worker. The file `src/modules/temporal/workflows/process-agent.workflow.ts` still exists, but `workflows/index.ts` does not export it, so the Temporal worker has no workflow by that name.
</Warning>

The function body is a placeholder: everything except `return results` is commented out, so it would return an empty object even if it were registered.

The main API still has a route that starts it: `POST /process/agent` in back's `src/temporal/temporal.controller.ts` calls `client.start('processAgent', …)` with `args: [flowId, user.id]`. Because no worker registers the workflow type, the workflow tasks of a run started there fail and it never runs a node.

## What runs a full agent instead

A full agent run goes through the main API's `apiV2` path in back's `src/app-api/flux/flux.service.ts`. When the `engine_in_workflow` feature flag is on and every node type in the flow is eligible, `apiV2` starts the `processFlow` workflow, which dispatches a child [`processSingleNode`](/worker/workflows/process-single-node) per node. Otherwise the main API's own loop orchestrates the nodes and starts `processSingleNode` for each worker-executed node. See [Worker service](/worker/workflows/worker-service#registered-workflows) for every workflow the worker registers.
