## Overview

The `generateFileActivity` creates output files from node execution results. It's used when nodes are configured to save their output to a file.

## Purpose

- Generate output files from node results
- Save node outputs for later retrieval
- Provide file URLs for download
- Support file-based output storage

## When it's executed

This activity is called conditionally:

1. **After successful execution**: Only when `saveOutput` is enabled in node configuration
2. **When file type is specified**: Requires `fileType` to be configured
3. **Before completion**: Executes before marking the workflow as complete

## Signature

```typescript
async generateFileActivity({
  nodeId: string,
  fileType: string
}): Promise<string>
```

## Inputs

| Parameter | Type | Description |
|-----------|------|-------------|
| `nodeId` | `string` | ID of the node generating the file |
| `fileType` | `string` | File extension/type (e.g., `txt`, `json`, `md`) |

## Outputs

Returns the `file` field from the main API's JSON response (a URL string pointing to the generated file).

## Implementation details

<Warning>
This activity makes a real HTTP call — it is not a stub — but it is currently **dead code**: nothing in `process-single-node.workflow.ts` (or any other live workflow) invokes `generateFileActivity`. The only reference to it in a workflow is a commented-out block in `process-agent.workflow.ts` (`process-agent`, a workflow that is itself not wired into the active node-dispatch path). Until something calls it, this activity never runs in production.
</Warning>

The implementation makes a real `POST ${URL_MAIN_API}/worker/generate-file` request with `{ nodeId, fileType }` in the body and the standard `internal-api-key` header, and returns `data.file` from the parsed JSON response. The actual file generation happens on the main API side, not in this activity — the worker only forwards the request and relays the resulting URL.

## Example usage in workflow

```typescript
// Check if file generation is enabled
if (node.data.saveOutput && node.data.fileType) {
  const fileUrl = await generateFileActivity({
    nodeId,
    fileType: node.data.fileType,
  });

  if (!fileUrl) {
    throw new Error("Failed to generate file");
  }

  // File URL can be saved to database or returned to user
  // TODO: Save fileUrl to database
}
```

## Configuration

File generation is controlled by node configuration:

- `saveOutput`: Boolean flag enabling file generation
- `fileType`: String specifying the file extension/type

## Supported file types

The activity accepts any file type string. Common types include:

- `txt` - Plain text files
- `json` - JSON data files
- `md` - Markdown files
- `csv` - CSV data files
- `html` - HTML files

## Error handling

The activity may return an empty string or throw an error if:

- File generation fails
- The file type is invalid
- Storage is unavailable
- The node ID is invalid

The workflow should validate the returned URL:

```typescript
const fileUrl = await generateFileActivity({
  nodeId,
  fileType: node.data.fileType,
});

if (!fileUrl) {
  throw new Error("Failed to generate file");
}
```
