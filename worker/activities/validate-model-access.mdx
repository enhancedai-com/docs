## Overview

The `validateModelAccessActivity` asks the main API whether the plan behind a flow can use a given AI model and provider. It lives in `src/modules/temporal/activities/activities.service.ts`.

<Warning>
The check does not block the run today. `processSingleNode` awaits the activity but ignores the returned value, and the activity returns `false` instead of throwing when access is refused. A refusal is only visible in the worker log (`validate-model-access refused`). Whether a paying plan exists is enforced earlier by `nodeCreditGateActivity`, which throws a `UserConfigError` (status 402) when the back refuses the node.
</Warning>

## When it's executed

`processSingleNode` calls it only for the Text Generator (`commandTextNode`), inside the cancellation scope and right before `textGeneratorActivity`, with the `aiModel` and `aiSystem` read by `getNodeInfoActivity`.

## Signature

```typescript
async validateModelAccessActivity({
  flowId: string,
  model: string,
  aiSystem: string
}): Promise<boolean>
```

## Inputs

| Parameter | Type | Description |
|-----------|------|-------------|
| `flowId` | `string` | ID of the flow requesting model access |
| `model` | `string` | Model identifier to validate |
| `aiSystem` | `string` | AI system/provider (for example `openai`, `anthropic`) |

## Outputs

Returns `data.success` from the back's JSON reply: `true` when access is validated, `false` when the back refuses. A reply without `success` (for example a 401 from the internal API guard) returns `undefined`. When the reply is not `ok` or not successful, the activity logs `validate-model-access refused` with `flowId`, `model`, `aiSystem`, the status code, message and error code.

## Implementation details

```
POST ${URL_MAIN_API}/worker/validate-model-access
```

- **Request body**: `{ flowId, model, aiSystem }`
- **Header**: `internal-api-key` with `INTERNAL_API_KEY`
- There is no retry inside the activity. The Temporal proxy runs it with `maximumAttempts: 1` and a 60-second `startToCloseTimeout` (`SINGLE_ATTEMPT_GROUP_TIMEOUT_MS`), so a network error or a non-JSON reply fails the activity and the node.

## Back endpoint

`WorkerController.validateModelAccess` in `back/src/temporal/worker.controller.ts`:

- It resolves the provider from `model` and `aiSystem`, builds the plan filter with `buildAiSystemWhere`, and looks up the paying user product with `productService.getUserProductFromFlow(flowId, aiSystemWhere, model)`.
- **No matching product**: `403 { success: false, message: 'User does not have access to this model' }`
- **Match**: `200 { success: true, message: 'Model access validated' }`

## Example usage in workflow

```typescript
const output = await cancelScope.run(async () => {
  await validateModelAccessActivity({
    flowId: node.flow_id,
    model: node.data.aiModel,
    aiSystem: node.data.aiSystem,
  });
  return await textGeneratorActivity({ execId, nodeId, sessionId, userId, flowId, flowVersionHistoryId, runToken, socketId });
});
```
