## Overview

The `notifyStatusActivity` sends real-time status updates to users about the execution status of nodes in a workflow. This activity is used throughout the workflow execution lifecycle to keep users informed of progress.

## Purpose

- Notify users when node execution starts
- Update users when nodes complete successfully
- Alert users when nodes fail
- Provide real-time feedback on workflow progress

## When it's executed

`processSingleNode` calls it at four points:

1. **Node start**: first thing in the workflow (status: `PENDING`)
2. **Node completion**: after the success log is written (status: `COMPLETED`)
3. **Node failure**: after the error log is written (status: `FAILED`, with `userMessage` and `message` both set to the user-facing message)
4. **Node cancellation**: after the cancelled node is settled (status: `CANCELLED`)

## Signature

```typescript
async notifyStatusActivity({
  nodes: Record<string, NodeStatusUpdate>,
  userId: string,
  flowId: string,
  execId?: string,
  runId?: string,
  flowVersionHistoryId?: string | null,
}): Promise<void>
```

## Inputs

| Parameter | Type | Description |
|-----------|------|-------------|
| `nodes` | `Record<string, NodeStatusUpdate>` | Object mapping node IDs to their status objects. `NodeStatusUpdate` is `{ status: NodeStatus; userMessage?: string; message?: string }`, where `NodeStatus` is `PENDING`, `RUNNING`, `COMPLETED`, `FAILED` or `CANCELLED`. The text fields are set on failure |
| `userId` | `string` | ID of the user to notify |
| `flowId` | `string` | ID of the flow containing the nodes |
| `execId` | `string` (optional) | Execution id for this notification |
| `runId` | `string` (optional) | Workflow run id |
| `flowVersionHistoryId` | `string \| null` (optional) | Version history id for the flow |

## Outputs

Returns `void`. The activity completes once the event is handed to the Redis client; it does not wait for the browser to receive it.

## Implementation details

The activity passes the payload to `NotificationService.sendStatusUpdate` (`src/modules/notification/notification.service.ts`). The service emits the `room_status_updated` event (`RUN_STATUS_UPDATED` in `notification-events.ts`) through a NestJS Redis `ClientProxy` registered as `REDIS_SERVICE`, using `REDIS_HOST` and `REDIS_PORT` (default `6379`).

On the back, `TemporalController.handleRoomUpdated` (`back/src/temporal/temporal.controller.ts`) listens for `room_status_updated` and calls `NotificationsGateway.sendToUser`, which emits the same event over Socket.io to the flow room of `userId` and `flowId`. The front reads node status from that socket event.

## Example usage in workflow

```typescript
// Notify that execution is starting
await notifyStatusActivity({
  nodes: {
    [nodeId]: {
      status: "PENDING",
    },
  },
  userId,
  flowId,
  execId,
  flowVersionHistoryId,
  runId,
});

// Notify successful completion
await notifyStatusActivity({
  nodes: {
    [nodeId]: {
      status: "COMPLETED",
    },
  },
  userId,
  flowId,
  execId,
  flowVersionHistoryId,
  runId,
});

// Notify failure
await notifyStatusActivity({
  nodes: {
    [nodeId]: {
      status: "FAILED",
      userMessage: detail.userMessage,
      message: detail.userMessage,
    },
  },
  userId,
  flowId,
  execId,
  flowVersionHistoryId,
  runId,
});
```

## Status values

| Status | Description | When used |
|--------|-------------|-----------|
| `PENDING` | Node execution has started | At workflow start |
| `RUNNING` | Node is running | Part of the `NodeStatus` type; `processSingleNode` does not send it |
| `COMPLETED` | Node executed successfully | After successful completion |
| `FAILED` | Node execution encountered an error | When an error occurs |
| `CANCELLED` | Node run was cancelled | After a cancelled node is settled |
