## Overview

The worker reads and writes some tables of the back's database directly through its own `pg` pool (`DatabaseService`): `node_executions`, `execution_logs`, `flows_nodes` and the batch tables, among others. Everything that needs the back's services goes over HTTP instead: S3 claim-check storage, entitlement checks, billing, file and media storage, OAuth token refresh, and run bookkeeping. The back exposes those as `/worker/*` endpoints in `src/temporal/worker.controller.ts`. The whole controller sits behind `InternalApiGuard`, which compares the `internal-api-key` request header with the back's `INTERNAL_API_KEY` and answers `401` when they differ. The worker builds every URL from `URL_MAIN_API`.

This page details the endpoints a node author most often needs. [Other endpoints](#other-endpoints) lists the rest.

## Reference

### `/worker/store-payload` {#store-payload}

Claim-check write for payloads larger than 256 KB (262144 bytes; both sides read the override from `CLAIM_CHECK_THRESHOLD_BYTES`). The wire contract is pinned by `src/modules/nodes/shared/claim-check.contract.json`, an identical file in both repos.

**Request**

```ts
interface StorePayloadRequest {
  execId: string;
  nodeId: string;
  payload: unknown;
  runToken?: string;
  field?: 'output' | 'resolved' | 'subRunInput' | 'result';
}
```

`field` defaults to `output`. `resolved` stores the input the worker resolved for a node. `result` stores the result of a whole run under `node-exec/<execId>/run-result.json`, with `execId` carrying the run id.

**Response**

```ts
interface StorePayloadResponse {
  success: true;
  key: string;
}
```

**Auth model**

Guarded by `InternalApiGuard`. Keys are additionally bound to their run by `ClaimCheckAuthzService.authorizeWrite`, which validates the `(execId, nodeId, runToken)` triple before any S3 write; a `result` write goes through `authorizeRunWrite` with the run id and token instead. An invalid `field` is a `400`. See [TASK-S5 — Claim-check authorization](https://github.com/enhancedai-com/Workflow/blob/main/.claude/tasks/worker-flow-execution-epic/TASK-S5-CLAIM-CHECK-AUTHZ.md).

**Side effects**

Serializes the payload and uploads it to the private claim-check S3 bucket under a deterministic key (`node-exec/<execId>/<nodeId>-<field>.json`). Returns the key the worker stores inside a `{ __claimRef: key }` envelope on `outputData`.

**When to use**

A payload the activity needs to persist whose serialized size exceeds the threshold.

**When not to use**

Calling it yourself from a node: `persistNodeSuccess` (`src/modules/nodes/shared/persist-node-success.ts`) already measures the payload and, through `offloadIfLarge` in `persist-node-outcome.ts`, offloads it through this endpoint when it is over the threshold. Small payloads go straight into `outputData`.

### `/worker/get-payload` {#get-payload}

Claim-check read: resolves a `{ __claimRef: key }` envelope back into the original payload stored in private S3.

**Request**

```ts
interface GetPayloadRequest {
  key: string;
  execId?: string;
  nodeId?: string;
  runToken?: string;
}
```

**Response**

```ts
interface GetPayloadResponse {
  success: true;
  payload: unknown;
}
```

**Auth model**

Guarded by `InternalApiGuard`. The `key` must start with `CLAIM_CHECK_KEY_PREFIX` (`node-exec/`) or the request is rejected with a `400`. `ClaimCheckAuthzService.authorizeRead` then derives the exec id and node id from the key itself, checks the key is bound to a stored row and that the `runToken` matches, and answers `403` otherwise. The declared `execId` and `nodeId` are only logged on a refusal.

**Side effects**

Reads the object from the claim-check bucket, streams it, and JSON-parses it. Read-only.

**When to use**

An activity is about to consume an upstream node's output whose value is a claim-check reference instead of the inline payload.

**When not to use**

Inline payloads (the common case): the value is already available on `outputData` and no HTTP call is needed.

### `/worker/validate-model-access` {#validate-model-access}

Pre-execution authorization check: confirms the user behind the flow is entitled to call the requested model. `validateModelAccessActivity` calls it before a Text Generator runs.

**Request**

```ts
interface ValidateModelAccessRequest {
  flowId: string;
  model: string;
  aiSystem: string;
}
```

**Response**

```ts
interface ValidateModelAccessResponse {
  success: boolean;
  message: string;
}
```

Returns HTTP 200 with `success: true` when the entitlement check passes, HTTP 403 with `success: false` when the user has no matching `user_product` for the resolved provider.

**Auth model**

Guarded by `InternalApiGuard`. The provider is resolved from `system_ai_models` (`SystemAiModelsService.resolveProviderForModel`, falling back to the `aiSystem` sent). For Anthropic, Gemini, Perplexity, Stability AI, Ideogram and open-source models, the product must also carry that provider's plan flag. Entitlement is then read from the flow's owning user product with `ProductService.getUserProductFromFlow`.

**Side effects**

None. Read-only check against `user_products` and `system_ai_models`.

**When to use**

Before invoking any paid AI model from an activity, so a 403 surfaces as a `UserConfigError` instead of a provider-side billing failure.

**When not to use**

Deterministic, non-billed operations (local scripting, math, pure data transforms) — there is no entitlement to check.

### `/worker/charge-tokens` {#charge-tokens}

Post-execution billing: records the tokens a model actually consumed. The Text Generator, the Image Generator and the Image Reader call it.

**Request**

```ts
interface ChargeTokensRequest {
  flowId: string;
  userId: string;
  inputTokens: number;
  outputTokens: number;
  model: string;
  aiSystem: string;
  execId?: string;
  nodeId?: string;
  label?: string;
  usedTokens?: number;
  billingFlowId?: string;
  webSearchCalls?: number;
  nodeType?: string;
}
```

`label` defaults to `Text`. `nodeType` selects a credit multiplier: for `imageReaderNode`, when the `image_reader_credit_multiplier` feature flag is on, its value (at least `1`) multiplies the charge; every other type is charged at `1`.

`webSearchCalls` is the number of web search tool calls the model made. The back bills them as an extra charge line only when the resolved provider has a web search price key (OpenAI and Anthropic). For other providers, including Gemini, the field has no effect.

**Response**

```ts
interface ChargeTokensResponse {
  success: boolean;
  message: string;
  tokens?: number;
  cost?: number;
}
```

Returns HTTP 200 with `tokens` and `cost` on success, HTTP 500 with `success: false` when `ProductService.updateTokens` cannot apply the charge.

**Auth model**

Guarded by `InternalApiGuard`. The user product is resolved from the flow (or from `billingFlowId` when it is set) via `ProductService.getUserProductFromFlow`, with the same provider plan flag as `/worker/validate-model-access`.

**Side effects**

Writes a `token_transaction` row and updates the user product's running token and cost totals. When you pass `execId` and `nodeId`, a repeated call does not charge again: the unique index `UQ_token_transaction_exec_node_api` on `(execId, nodeId, api)` keeps the same charge from being recorded twice, and a retry after a partial charge writes only the missing lines. Without them, calling twice charges twice.

**When to use**

A model call succeeded and real tokens were consumed. `execId` and `nodeId` should be passed so the transaction is traceable back to the specific run.

**When not to use**

Any failure path where the user did not consume tokens — in particular, a `UserConfigError` means the model never ran, so charging would inflate the user's bill.

### `/worker/charge-transcription` {#charge-transcription}

Post-execution billing for the [AI audio transcriber](/worker/node/audio-transcriber#billing) node: records the audio the node transcribed.

**Request**

```ts
interface ChargeTranscriptionRequest {
  flowId: string;
  userId: string;
  model:
    | 'whisper-1'
    | 'whisper-large-v3'
    | 'whisper-large-v3-turbo'
    | 'gemini-speech-to-text'
    | 'youtube-transcript';
  usedTokens: number;
  execId?: string;
  nodeId?: string;
}
```

`usedTokens` must be a number greater than or equal to `0`. The worker sends audio hours for the Whisper models, billed seconds for `gemini-speech-to-text`, and `1` for `youtube-transcript`. An unknown `model` is rejected by DTO validation.

**Response**

```ts
interface ChargeTranscriptionResponse {
  success: boolean;
  message?: string;
  usedTokens?: number;
  cost?: number;
}
```

Returns HTTP 200 with `success: true`, `usedTokens` and `cost` on success. Returns HTTP 403 with `success: false` when the flow's owner has no user product with the plan flag the model requires. Returns HTTP 500 with `success: false` when `ProductService.updateTokens` cannot apply the charge.

**Auth model**

Guarded by `InternalApiGuard`. The user product is resolved from the flow via `ProductService.getUserProductFromFlow` with the plan flag the model needs: `transcribe` for `whisper-1`, `groq` for the two Groq models, `gemini` for `gemini-speech-to-text`, and none for `youtube-transcript`.

**Side effects**

Writes a `token_transaction` row under the label `Audio` and updates the user product's running token and cost totals. When you pass `execId` and `nodeId`, a repeated call is a no-op: a unique index on `(execId, nodeId, api)` keeps the same charge from being recorded twice, and the response carries `usedTokens: 0` and `cost: 0`. Without them, calling twice charges twice.

**When to use**

The audio transcriber returned a `charge` for a transcription that completed. Pass `execId` and `nodeId` so the transaction is traceable to the run.

**When not to use**

Any path where nothing was transcribed (`charge` is `null`), and any failure before the transcription.

### `/worker/run-events` {#run-events}

Ingests a batch of run lifecycle events. The back stores the events and rebuilds the run log from them.

The worker calls it from `emitRunEventActivity`, which the `processFlow` workflow uses when it owns the flow loop (the `engine_in_workflow` path). When the back runs the loop itself, it records the same events in its own process.

**Request**

```ts
interface RunEventsRequest {
  runId: string;
  events: RunEvent[];
}

interface RunEvent {
  runId: string;
  seq: number;
  kind:
    | 'run_started'
    | 'node_started'
    | 'node_finished'
    | 'run_finished'
    | 'loop_body_started'
    | 'library_subrun_started'
    | 'flow_caller_subrun_started'
    | 'flow_caller_subrun_finished';
  execId?: string;
  nodeId?: string;
  nodeType?: string;
  flowId?: string;
  flowVersionHistoryId?: string;
  parentExecId: string | null;
  iteration: number | null;
  status?: 'success' | 'error' | 'cancelled';
  error: {
    userMessage: string;
    devMessage?: string;
    category?: string;
    field?: string;
  } | null;
  loop?: {
    anchorExecId?: string;
    items?: number;
    itemsProcessed?: number;
    cancelled?: boolean;
  };
  inputRef?: string;
  resultRef?: string;
  at: string;
}
```

`runId`, `execId`, `flowId`, `flowVersionHistoryId`, `parentExecId` and `loop.anchorExecId` are UUIDs. `seq` is an integer of at least `1`, `at` is an ISO 8601 timestamp, and `events` must contain at least one item. Every event's `runId` must match the batch's `runId`.

**Response**

```ts
interface RunEventsResponse {
  appliedThroughSeq: number;
  finished: boolean;
}
```

Returns HTTP 200. `appliedThroughSeq` is the highest `seq` stored for the run, and `finished` is `true` once a `run_finished` event exists. Returns HTTP 400 when an event's `runId` differs from the batch's, or when DTO validation fails.

**Auth model**

Guarded by `InternalApiGuard`. There is no per-run token check on this route.

**Side effects**

In one transaction, the back locks the run, inserts the events, and rebuilds the stored run log from every event of the run. An event whose `(runId, seq)` already exists is ignored, so resending a batch is safe. When a `run_finished` event with a `resultRef` arrives for a run that is still open, the back also finishes the run's execution record: it sets the final status, the output or error message, the token and cost totals from `token_transaction`, and the duration. A `cancelled` finish is recorded as status `error` with the message `Run cancelled`.

**When to use**

A component outside the back needs to report a run's node and run lifecycle so the back can build the run log.

**When not to use**

Reporting a node's output: this endpoint carries references (`inputRef`, `resultRef`) to payloads, not the payloads themselves. Store them with `/worker/store-payload` first.

### `/worker/generate-file` {#generate-file}

Takes text and renders it into a file, uploads the file to durable storage, and updates the node's `data.fileLink`/`data.fileLinks`. The Display Box and Report Builder nodes call it.

**Request**

```ts
interface GenerateFileRequest {
  nodeId: string;
  fileType: string;
  text?: string;
  customFileName?: string;
  useDocRaptor?: boolean;
  userId?: string;
  flowId?: string;
  flowVersionHistoryId?: string | null;
  spaceId?: string;
  provider?: string;
}
```

When `text` is omitted, the back resolves it from the node's own `data.text` via `FlowNodeService` (scoped to `flowVersionHistoryId` when provided).

**Response**

```ts
interface GenerateFileResponse {
  success: boolean;
  message: string;
  file: string;
  fileLink: {
    src: string;
    name: string;
  };
}
```

Returns HTTP 400 with `success: false` when no text is available (neither passed in nor resolvable from the node), HTTP 500 with `success: false` when upload fails.

**Auth model**

Guarded by `InternalApiGuard`. No per-user entitlement is checked at this layer — the file is attributed to `userId` for persistence into `generated_files`, but access control is the caller's responsibility.

**Side effects**

Uploads the rendered file through `UploadService.uploadText` (DocRaptor when `useDocRaptor` is set) and persists a `generated_files` row when `userId` is provided (provider `outputController` unless `provider` is sent). When the node is found, it then writes `data.fileLink` and appends the URL to `data.fileLinks` on its `flows_nodes` row. The node is looked up by `(flowId, nodeId, flowVersionHistoryId)` when `flowId` is sent, otherwise by `nodeId` alone.

**When to use**

A node needs to produce a durable file artifact (PDF, DOCX, etc.) and have the resulting URL propagated back onto its own `data`.

**When not to use**

Writing an arbitrary payload to storage: this endpoint renders text into a file format, it is not a general-purpose upload. For arbitrary large payloads use `/worker/store-payload`.

## When to use which

| Situation | Correct endpoint |
|---|---|
| About to persist a payload > 256 KB | `/worker/store-payload` |
| About to read a payload > 256 KB written by a previous activity | `/worker/get-payload` |
| About to invoke a model whose user may not have access | `/worker/validate-model-access` |
| Model call succeeded and tokens were consumed | `/worker/charge-tokens` |
| Audio transcription completed and returned a `charge` | `/worker/charge-transcription` |
| Need to report run and node lifecycle events so the back can build the run log | `/worker/run-events` |
| Need to render text into a file and attach it to the node | `/worker/generate-file` |

## When NOT to use

- Do not call `/worker/charge-tokens` on user error — a `UserConfigError` means the user did not consume tokens; charging anyway inflates their bill.
- Do not call `/worker/charge-transcription` when the transcriber returned no `charge` — nothing was transcribed.
- Do not call `/worker/generate-file` to store an arbitrary payload — it renders text into a file; large payloads go through `/worker/store-payload`.
- Do not call `/worker/store-payload` to bypass `persistNodeSuccess` — the row still has to be written; the claim check is additional, not alternative.

## Other endpoints

The controller also serves these routes. All are `POST` unless noted, and all sit behind the same `InternalApiGuard`.

| Endpoint | Worker caller | Purpose |
|---|---|---|
| `/worker/node-credit-gate` | `nodeCreditGateActivity` | Refuses a paid node when the paying account can no longer be charged |
| `/worker/validate-api-access` | `validateApiAccessActivity` | Entitlement check for an API capability (`google_search`, `google_news`, `sec_data`, `us_census_data`) |
| `/worker/charge-api-call` | `chargeApiCallActivity` | Bills one API-capability call |
| `/worker/charge-scrape` | Web Crawling (`charge-scrape.client.ts`) | Bills a scraping call by provider (`scrapingBee`, `oxylab`, `builtWithApi`) |
| `/worker/validate-large-memory-access` | `validateLargeMemoryAccessActivity` | Entitlement check before a Large Memory run |
| `/worker/charge-large-memory-usage` | `chargeLargeMemoryUsageActivity` | Bills a Large Memory run |
| `/worker/charge-voice` | `chargeVoiceActivity` | Bills a voice generation under the label `Audio` |
| `/worker/persist-generated-audio` | Voice generator (`persist-audio.client.ts`) | Records a `generated_audio` row; always answers `200` |
| `/worker/store-image` | Image Generator (`store-and-charge.ts`) | Stores a generated image and records it |
| `/worker/store-video` | AI Video Generator (`store-generated-video.ts`) | Stores a generated video from its source URL |
| `/worker/refresh-oauth-token` | `token-provider.service.ts` | Returns a fresh Google or Microsoft access token for a user |
| `/worker/delivery-outcome` | `reportDeliveryOutcomeActivity` | Records a failed output delivery; answers `204` |
| `GET /worker/run-seed/:id` | `loadRunSeedActivity` | Loads a run seed snapshot |
| `/worker/open-node-execution` | `openNodeExecutionActivity` | Opens the `node_executions` row for a node of a `processFlow` run |
| `/worker/api-run-finish` | `finishApiRunActivity` | Finishes an API run |
| `/worker/batch-row-run` | `prepareBatchRowRunActivity` | Prepares the run of one batch row |
| `/worker/batch-row-outputs` | `finishBatchRowRunActivity` | Records a batch row's outputs |
| `/worker/scheduled-run` | `prepareScheduledRunActivity` | Prepares a scheduled run |
| `/worker/scheduled-run-outputs` | `finishScheduledRunActivity` | Records a scheduled run's outputs |

Verify the list against `src/temporal/worker.controller.ts` in back before relying on it.
