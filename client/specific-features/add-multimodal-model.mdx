## Location

Model metadata is no longer a static constants array in the frontend. It is managed through the **Admin Panel** at `/admin/ai-models` (`src/views/AdminDashboard/AiModelsManagementPage.tsx`), an admin-only route backed by `AdminAiModelsService` (`src/service/AdminAiModelsService.ts`), which calls the `/model_price` API endpoints.

<Note>
  The former `src/components/AiConfigs/constants.ts` provider arrays (`optionsArray`, `anthropicOptions`, `geminiOptions`, `groqOptions`, `xAiOptions`) no longer exist in the codebase. Model data now lives in the database and is edited through this admin page, not committed to source.
</Note>

## Data shape

Each row in the admin table is a `ModelPriceResponse` (a price entry), optionally linked to a `SystemAiModelResponse` (the model's technical metadata):

```typescript
export interface AiModelTag {
  label: string;
  tooltip: string;
}

export interface SystemAiModelResponse {
  id: string;
  aiCompany: string;
  modelName: string;
  modelType: string;
  maxInputToken: number | null;
  maxOutputToken: number | null;
  contextWindow: number | null;
  isVisionModel: boolean;
  supportsReasoning: boolean;
  reasoningAlwaysOn: boolean;
  supportsWebSearch: boolean;
  supportsStructuredOutput: boolean;
  supportsStreaming: boolean;
  supportsTemperature: boolean;
  supportsImageGenerationTool: boolean;
  isActive: boolean;
  isDeprecated: boolean;
  isDefault: boolean;
  description: string | null;
  displayName: string | null;
  tags: AiModelTag[] | null;
}
```

Multimodal/vision support is a structured `isVisionModel` boolean (shown as the **Vision** column in the table), not a tag convention. Tags remain free-form `{ label, tooltip }` pairs for anything the structured fields don't cover, such as attachment-count or file-size limits.

## Tag format

Tags are still objects with `label` and `tooltip`, defined by `AiModelTag` in `src/service/AdminAiModelsService.ts`:

```typescript
tags: [{ label: 'Label Text', tooltip: 'Tooltip description' }]
```

<Warning>
  Plain string tags are not supported by the type. Every tag needs both `label` and `tooltip`.
</Warning>

## Managing a model

<Steps>
  <Step title="Open the Admin Panel">
    Go to `/admin/ai-models`. The page lists every `ModelPriceResponse` row with its AI company, model type, flux conversion rate, and whether it's linked to a `SystemAiModel`, active, deprecated, vision-capable, streaming-capable, or the provider default. A search box filters by model name or AI company.
  </Step>
  <Step title="Create or edit">
    Use **Create Model** to add a new price entry, or click an existing row to open its edit modal.
  </Step>
  <Step title="Set capability flags">
    The edit modal exposes switches for the structured capability fields (`isVisionModel`, `supportsStreaming`, `supportsReasoning`, `supportsWebSearch`, `supportsStructuredOutput`, `supportsImageGenerationTool`, `supportsTemperature`).
  </Step>
  <Step title="Add tags">
    A tags editor lets you add label/tooltip pairs for anything not covered by a structured field. Click an existing tag chip to edit it in place, or its delete icon to remove it.
  </Step>
</Steps>

## Verification

After changing a model:

1. Confirm the row reflects the new values in the admin table (e.g. the **Vision** or **Active** columns)
2. Verify any new tag displays with the correct label and tooltip
3. Make sure the backend actually supports the model for multimodal requests — this admin page only manages display/config metadata
