## What this does for you

**MCP (Model Context Protocol)** lets your workflow talk to an external service that exposes **tools** — actions the service can run for you, such as fetching data, creating records, or running calculations. The **MCP Client** node (node type `mcpNode`) picks one tool, sends it instructions, and stores the result in the node's output so the next steps in your flow can use it.

Think of it as a **bridge**: your flow stays in the product, while the heavy lifting happens on a vendor's or your team's MCP-compatible server.

## Quick glossary

| Term | Meaning |
|------|---------|
| **MCP server** | A web address (URL) that speaks the MCP protocol over HTTPS |
| **Tool** | A named action the server offers. You choose one tool per run. |
| **Bearer token** | A secret string some servers require. Treat it like a password. |
| **Workspace** | Your team or company context. Saved connections need a workspace. |
| **Connection** | A saved MCP server (URL plus optional token or OAuth sign-in) that you create under **Integrations** and pick in the node. Workspace members can use connections created by teammates; secrets stay on the server. |

## Remote HTTP vs stdio

<Tabs>
  <Tab title="Remote HTTP">
    A public `https://` MCP endpoint with bearer or OAuth authentication. Same model as connecting to remote servers in the MCP spec.
  </Tab>
  <Tab title="Npm package (stdio / npx) — retired">
    This option is no longer offered when you create a connection, and a connection saved this way is
    refused when it runs, with a message asking you to re-create it against a remote URL. Running a
    vendor's package on our servers was dropped on purpose.

    If a vendor gives you **only** an npm package and **no** HTTPS URL, you cannot use it through the
    node today — ask the vendor for a hosted HTTPS endpoint.
  </Tab>
</Tabs>

## How it fits together

1. You create a **connection** (saved URL + optional token; if the server requires OAuth, you sign in when you connect)
2. You configure the **MCP Client** node to use that connection (or a custom URL)
3. The **backend** calls the remote server; the result appears in the node output

## Path A — Saved connection (URL and optional token)

Use **Integrations** when you have an HTTPS MCP URL and optionally a bearer token.

<Steps>
  <Step title="Open Integrations">
    Go to **Integrations**, find **MCP**, and choose **Connect**.
  </Step>
  <Step title="Enter credentials">
    | Field | What to enter |
    |-------|---------------|
    | **Connection Name** | Optional label for the connection (for example `My MCP`) |
    | **MCP server web address** | Full URL including `https://` (often ends with `/mcp`) |
    | **Secret token** | Only if the server docs say to send an API key or bearer token. Paste a raw token, a full header like `Authorization: Bearer ...`, or JSON like `{"scheme":"Bearer","token":"..."}` or `{"headers":{"x-api-key":"..."}}` |
  </Step>
  <Step title="Use it in the MCP Client node">
    1. Add an **MCP Client** node to your flow
    2. In the **Connection** section, pick the connection you created
    3. In the **Tool** section, click **Load tools**, then optionally pick a tool under **Select tool**
    4. Describe what you want in **Prompt** (under **Command**), or fill in the tool's **Arguments**, then run
  </Step>
</Steps>

## Path B — Server that requires OAuth (e.g. Magic Patterns)

Some providers use OAuth (a browser login) instead of a static API key. You still start from **Integrations**, with the same form as Path A.

<Steps>
  <Step title="Connect">
    In **Integrations**, find **MCP**, enter the server's web address, leave the token empty, and choose **Connect**. When the server asks for OAuth, a sign-in window opens. Complete the sign-in there.
  </Step>
  <Step title="Wait for the confirmation">
    The window closes by itself and FluxPrompt shows **Connected successfully**. The connection is now saved. If the sign-in fails, you see the provider's error message instead.
  </Step>
  <Step title="Configure the node">
    In the **MCP Client** node, pick the new connection under **Connection**. Load tools, optionally pick one, and run.
  </Step>
</Steps>

## Field-by-field reference

### MCP Server URL

The full HTTPS endpoint. With a workspace and a saved connection, this field is hidden. Without a workspace, enter it directly or connect another node's output to the URL handle.

### Connection

Lists the MCP connections from Integrations (yours and teammates'), including servers you signed in to with OAuth. The backend uses the stored URL and credentials via `integrationId`.

### Auth token

Manual bearer token when you are not using a saved connection. Hidden with a workspace and a saved connection unless the `authToken` handle is wired.

### Tool

1. **Load tools** — fetches the tool list from the server. The button is disabled until you pick a connection or enter a server URL, and it has a short cooldown after each click.
2. **Select tool** — optional; leave it on **Using prompt** to let the prompt pick the tool, or choose one to pin it
3. **Tool Name** — appears when you have no tool list loaded, or when the name comes from a handle wired from another node
4. **Arguments** — appears when the selected tool publishes a schema. Use **Show/Hide** to open the fields; required ones are marked with `*`.

### Command

**Prompt** — describe what you want in plain language. The prompt is never sent to the MCP server: FluxPrompt reads it to pick the tool when none is selected, and to fill the tool arguments you leave empty. It must not be empty.

### Prompt and arguments

There is no mode switch. What you fill in decides how the call is built:

| You set | What happens |
|---------|--------------|
| No tool selected (**Using prompt**) | The prompt picks the tool and builds its arguments. |
| A tool selected, **Arguments** left empty | The prompt fills the arguments from the tool's schema. |
| A tool selected, **Arguments** filled | The values are sent as-is; the prompt is not used to infer arguments. |

## Worked examples

<Accordion title="Official MCP reference host (HTTPS)">
  1. In **Integrations → MCP**, create a connection with the reference URL
  2. In the node, select that connection, click **Load tools**, optionally pick a tool
  3. Start with a simple instruction in **Prompt** and no arguments
</Accordion>

<Accordion title="Magic Patterns (OAuth)">
  1. In **Integrations → MCP**, enter the server's web address and choose **Connect**, then complete the OAuth sign-in window
  2. In the node, select the new connection under **Connection**
  3. Load tools, optionally pick a tool, use **Prompt** to describe the design or action
</Accordion>

<Accordion title="Bring your own remote MCP (Cloudflare or similar)">
  1. Deploy your server to get a stable `https://.../mcp` URL
  2. If the guide says "API key in Authorization: Bearer", paste that key when creating the connection
  3. Save, select the connection in the node, load tools, run
</Accordion>

## Chaining with other nodes

### Referencing this node's output

Use placeholders like `{{mylabel.text}}` where `mylabel` is the node's label (lowercased, no spaces) and `text` is the output field.

**Example:** if the node label is **GitHub MCP**, use `{{githubmcp.text}}`.

### Feeding the MCP node from upstream nodes

Connect handles into **MCP Server URL**, **Tool Name**, **Prompt**, **Arguments**, and **Auth token** so earlier steps supply values dynamically.

## Prompt vs Arguments decision tree

1. **Do you have exact values from the vendor's example?** → Select the tool and fill in **Arguments**
2. **Is the tool's purpose easy to describe in a sentence?** → Leave **Arguments** empty and describe it in **Prompt**
3. **Does the tool need very precise field names and zero interpretation?** → Select the tool and fill in **Arguments**

## Troubleshooting

| Problem | What to check |
|---------|---------------|
| Select a workspace | Saved HTTP and some OAuth flows need workspace context |
| No tools / empty list | Wrong URL, missing `https://`, token missing or expired |
| Tool not in list | Click **Load tools** again after changes |
| OAuth sign-in window shows an error | Reconnect from **Integrations**; the message names what the provider rejected |
| Prompt errors | **Prompt** must not be empty ("Prompt is required") |
| Arguments errors | **Arguments (JSON)** must be a single JSON object such as `{"query":"invoices"}`; an empty object counts as unset |
| Long wait / timeout | Remote servers can be slow; retry or narrow the request |
| Connection not ready (canvas) | Wait for the live connection to finish, then run again |

## Security and hygiene

<Warning>
  Treat bearer tokens like passwords. Revoke them if exposed. Only connect to trusted MCP URLs.
</Warning>

- Prefer saved connections over pasting secrets into the node
- Workspace members can use connections created by teammates, so share a connection only when your organization approves it
- Copying a flow to another workspace does not transfer integration access
