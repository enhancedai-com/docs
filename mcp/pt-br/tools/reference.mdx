## O que a Fase 2 acrescenta

A Fase 1 expunha três ferramentas somente leitura. A Fase 2 expõe **28**: toda a superfície de leitura, autoria, versionamento e execução, para que um cliente MCP construa e execute um agente de ponta a ponta sem abrir o builder.

## Escopos

Um token carrega um ou mais escopos. Cada ferramenta abaixo indica o que exige; uma chamada sem ele é recusada com `-32401` e `data.required` nomeando o escopo faltante.

| Escopo | Permite |
|---|---|
| `read` | Listar e inspecionar agentes, pastas, versões e tipos de node |
| `write` | Criar e editar agentes, pastas, nodes, arestas e versões |
| `execute` | Iniciar execuções, ler resultados, cancelar |

<Note>
Os escopos são planos e por workspace. O `execute` cobre tanto iniciar uma execução quanto ler sua saída, então um cliente que só precisa inspecionar resultados também precisa ser confiável para iniciá-los.
</Note>

## Regras válidas para todas as ferramentas

### Dry-run é o padrão em tudo que escreve

Toda ferramenta que altera algo aceita `dryRun`, e o padrão é **true**. Um dry-run informa o que mudaria e não aplica nada. Para aplicar, envie `dryRun: false` **e** um `idempotencyKey`.

O `idempotencyKey` é escopado por (workspace, ferramenta, chave), então a mesma string pode ser reutilizada entre ferramentas diferentes. Um reenvio com a mesma chave e o mesmo payload devolve o resultado em cache em vez de agir duas vezes. O cache expira em 24 horas.

### workspaceId

Obrigatório apenas quando sua autorização cobre mais de um workspace. Use `list_workspaces` para ver quais são.

### Paginação

`list_agents`, `list_folders` e `list_versions` devolvem `{ itens…, total }` e, quando há mais resultados, um `nextCursor`. Reenvie-o como `cursor` com os **mesmos** demais argumentos — um cursor está vinculado aos argumentos que o produziram.

### O que a resposta diz além do resultado

| Campo | Significado |
|---|---|
| `unknownArguments` | Argumentos enviados que a ferramenta não declara. Foram **ignorados** — verifique, porque a ferramenta fez algo diferente do que você pediu. |
| `invalidEnumValues` | Campo de node com valor fora do enum declarado. A escrita foi aplicada, mas o executor não reconhece o valor e o node não fará nada. |
| `missingRequiredFields` | No `check_agent_integrity`: campo obrigatório do node deixado vazio. |
| `conditionRouting` | Em nodes que ramificam: quais handles o escalonador consegue de fato emitir. |
| `placementAdjusted` | O servidor moveu o node para não sobrepor outro. |

### Erros

| Código | Significado | `data` |
|---|---|---|
| `-32401` | Falha de autenticação ou escopo insuficiente | `reason` ou `required` |
| `-32602` | Parâmetros inválidos | `missing` (parâmetros omitidos) ou `invalid` |
| `-32005` | Kill switch ligado | — |
| `-32006` | Rate limit ou circuito aberto | `reason`, `retryAfterMs`, `hint` |
| `-32601` | Método desconhecido | — |
| `-32603` | Erro interno | — |

## As ferramentas

### Descoberta — sem escopo

| Ferramenta | Para quê |
|---|---|
| `list_workspaces` | Os workspaces que a autorização cobre, com seus escopos. Chame primeiro quando o token abrange mais de um. |
| `list_node_types` | O catálogo de nodes: tipo, rótulo, categoria, descrição. Sem schemas — use `get_node_type` para isso. |

### Leitura — `read`

| Ferramenta | Para quê |
|---|---|
| `list_agents` | Agentes do workspace, paginado. Filtre por `search`, `folderId` ou `folderName`. |
| `get_agent` | Um agente com nodes e arestas. `includeNodes: false` devolve só os metadados. |
| `list_folders` | Pastas, com `scope` (`space`/`personal`) e `spaceName` — um workspace costuma ter várias pastas de mesmo nome. |
| `list_versions` | Histórico de versões de um agente, com `isDeployed` e `isStaging`. |
| `get_node_type` | `inputSchema`, `outputSchema` e `handles` de um tipo. **Leia antes de criar um node** — valores de enum e campos companheiros vêm daqui. |
| `list_ai_models` | Modelos disponíveis no workspace, com provedor e `modelType`. |
| `check_agent_integrity` | Se o fluxo consegue executar: falta de ponto de entrada, arestas que não renderizam, arrays companheiros vazios, nodes inalcançáveis. |

### Autoria — `write`

| Ferramenta | Para quê |
|---|---|
| `create_folder` | Cria uma pasta. |
| `rename_folder` · `remove_folder` | Renomeia ou exclui. |
| `create_agent` | Cria um agente dentro de uma pasta. `empty: true` começa com tela em branco — recomendado quando você mesmo vai adicionar os nodes. |
| `update_agent` · `remove_agent` | Renomeia ou exclui um agente. |
| `move_agent` | Move um agente para outra pasta. `targetFolderId` precisa nomear uma pasta; mover para a raiz é recusado. |
| `add_node` · `update_node` · `remove_node` | Adiciona, altera ou remove um node. O `update_node` mescla `patch.data` em um nível, preservando as chaves omitidas. |
| `connect_nodes` · `disconnect_nodes` | Liga ou desliga dois nodes. Sem handles, o `connect_nodes` cria a aresta de execução, a de dados **e** a referência companheira numa só chamada. |
| `create_version` | Tira um snapshot da cópia de trabalho como versão. |
| `publish_version` | Publica uma versão **em produção**. Não existe alvo de staging. |

### Execução — `execute`

| Ferramenta | Para quê |
|---|---|
| `run_agent` | Inicia uma execução. Devolve um `runId`. |
| `get_run_status` | Status, tokens, custo, duração, erro. **Um run `completed` não prova que algum node produziu algo.** |
| `get_run_nodes` | Estado e prévia de saída por node da execução. |
| `get_node_output` | Saída de um node. Segredos são redigidos; saídas grandes são truncadas e avisam. |
| `cancel_run` | Solicita o cancelamento de um agente em execução. |

## Criando um agente que realmente executa

A ordem importa, e cada passo existe porque pular um produz um fluxo que salva e depois não faz nada:

<Steps>
  <Step title="Leia o contrato do node">
    `get_node_type` para cada tipo que for usar. Copie os valores de enum **literalmente** — um valor não reconhecido aparece em `invalidEnumValues` e transforma o node num no-op.
  </Step>
  <Step title="Crie o container">
    `create_folder` e depois `create_agent` com `empty: true`.
  </Step>
  <Step title="Adicione um globalStarter">
    O id precisa conter o literal `flow-global-starter`. O motor encontra a entrada do fluxo casando essa substring no id — qualquer outro id salva e o fluxo nunca inicia.
  </Step>
  <Step title="Adicione os nodes e conecte">
    Chame `connect_nodes` sem handles e deixe que ele monte a aresta de execução, a de dados e a referência companheira juntas.
  </Step>
  <Step title="Valide antes de executar">
    O `check_agent_integrity` precisa retornar `ok: true`.
  </Step>
  <Step title="Execute e verifique">
    `run_agent` e depois `get_run_nodes` — não apenas `get_run_status`.
  </Step>
</Steps>

## Tipos de node que não produzem nada durante a execução

Onze tipos são resolvidos pelo builder, que chama o provedor pelo navegador. Colocados num fluxo, reportam `completed` e guardam apenas a própria configuração: `imageReaderNode`, `animationNode`, `commandMusicNode`, `storedDataCaller`, `deepRefNode`, `documentSummarizer`, `webAmazon`, `webTrends`, `usCensusNode`, `secApiNode`, `hubSpotCRM`.

As descrições deles trazem um aviso `RUNTIME BEHAVIOUR`. Não os use como etapa da qual outro node vai ler.
