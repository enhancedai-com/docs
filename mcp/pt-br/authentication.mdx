## Dois métodos de autenticação

O servidor MCP de entrada do FluxPrompt suporta **dois** modos de autenticação. Qual deles você usa depende do seu cliente:

| Método | Quando usar | O que você faz |
|---|---|---|
| **OAuth 2.0** | Claude Desktop e Claude.ai (**obrigatório** — eles rejeitam tokens colados) e, opcionalmente, Claude Code / CLI e Cursor | Adiciona a URL do servidor como conector e faz login por uma tela de consentimento do FluxPrompt — **sem token** |
| **Service token estático** | Serviços de backend / máquina-a-máquina, a CLI, Cursor e n8n — clientes que não podem ou não devem executar um fluxo de consentimento no navegador | Gera um token e o coloca no header `Authorization` |

<Info>
**Usuários do Claude Desktop e do Claude.ai NÃO usam token.** Esses clientes rejeitam tokens bearer colados pelo usuário, então autenticam exclusivamente via OAuth. Se algum guia mandar você colar um token no Claude Desktop, ele está desatualizado — veja [Conectar Claude Desktop](/mcp/pt-br/connect/claude-desktop).
</Info>

## Método 1 — OAuth 2.0

OAuth é a escolha certa para qualquer cliente que consegue abrir um navegador. Você nunca vê nem manipula um token.

1. No seu cliente, adicione `https://mcp.fluxprompt.ai/mcp` como conector personalizado.
2. O cliente abre uma tela de login + consentimento do FluxPrompt.
3. Você faz login, **seleciona qual workspace** quer liberar e aprova.
4. O cliente armazena a autorização resultante automaticamente e a renova quando necessário.

Isso é **obrigatório** para Claude Desktop e Claude.ai, e **suportado** por Claude Code / CLI e Cursor. Veja os guias por cliente para os passos exatos.

## Método 2 — Service token estático

Para clientes máquina-a-máquina (serviços de backend), a CLI, o Cursor e o n8n, você usa um **service token** em vez de um fluxo no navegador.

### Gerar um service token

O dono do workspace gera um na interface do FluxPrompt:

1. Abra [**Settings → MCP Tokens**](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens).
2. Crie um novo token e escolha o workspace a que ele dá acesso.
3. Copie o token — ele começa com `mcp_` e é **exibido apenas uma vez**. Guarde-o em local seguro.

### Usar o token

O token vai no header `Authorization` de cada requisição MCP:

```
Authorization: Bearer mcp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Normalmente você não digita esse header à mão — seu cliente o lê de um arquivo de configuração (veja os guias de conexão para [Cursor](/mcp/pt-br/connect/cursor), [n8n](/mcp/pt-br/connect/n8n) e [desenvolvimento local](/mcp/pt-br/connect/local-dev)).

## Segurança do service token

<Warning>
Um service token concede acesso de leitura completo aos agentes do seu workspace. Trate-o como uma senha:
- Nunca o commite em um repositório Git.
- Nunca o cole em um documento público ou screenshot.
- Nunca o compartilhe no Slack, e-mail ou em qualquer mensagem que outras pessoas possam ver.
</Warning>

Se você acredita que um service token foi exposto:

1. Revogue-o em [**Settings → MCP Tokens**](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens).
2. Gere um novo.
3. Atualize seus arquivos de configuração do cliente com o novo token.

## Escopos

Uma chave carrega um ou mais de três escopos:

| Escopo | Concede |
|--------|---------|
| `read` | Listar agentes e pastas, buscar a estrutura completa de um agente, navegar tipos de node e modelos de IA. |
| `write` | Criar e editar agentes, pastas, nodes e edges; criar snapshots e publicar versões. |
| `execute` | Executar um agente, acompanhar uma execução, cancelar uma execução. |

Nenhum escopo dá acesso a faturamento, usuários ou configurações do workspace — isso nunca é exposto
via MCP.

### Uma chave é vinculada a um workspace

Cada chave é emitida para **uma** organização, escolhida na tela de consentimento (OAuth) ou pelo
workspace em que o token foi criado. Para atuar em outra organização, você autoriza de novo e mantém
uma segunda chave.

### Os escopos são reduzidos pelo seu papel

Se você não é admin da organização selecionada, pedir `write`/`execute` gera uma chave reduzida a
`read`, em vez de um erro. Um admin do workspace pode liberar isso com o toggle
**Allow non-admin write/execute keys** em
[Settings → MCP Tokens](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens) — desligado por
padrão.

### Alterar os escopos de uma chave

Um admin do workspace pode alterar os escopos de uma chave existente a qualquer momento — não é preciso
revogá-la e emitir outra. Em [Settings → MCP Tokens](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens),
a célula de escopos de cada chave na tabela **MCP Keys** mostra os escopos atuais como chips, com um
ícone de edição (lápis) ao lado. Clique nos chips ou no ícone, marque os escopos desejados e salve.
Quem não é admin vê os mesmos chips apenas como leitura.

Quanto tempo a mudança leva para chegar ao cliente depende da direção:

| Mudança | Quando passa a valer |
|---------|----------------------|
| Remover um escopo (ex.: `read` + `write` → `read`) | Imediatamente — a API principal lê os escopos atuais da chave em cada chamada. |
| Adicionar um escopo (ex.: `read` → `read` + `write`) | Em até `MCP_TOKEN_CACHE_TTL` segundos — **10 por padrão**. |

O servidor MCP mantém em cache a chave resolvida, escopos incluídos, por `MCP_TOKEN_CACHE_TTL` segundos
para evitar uma ida à API principal em cada chamada. Por isso, logo depois de um admin conceder `write`,
o cliente pode continuar sendo recusado por alguns segundos. Tente de novo depois de ~10 segundos ou
reconecte o cliente.

<Note>
O cache só pode atrasar uma concessão — ele nunca libera mais acesso do que a chave carrega no momento,
porque a API principal valida cada chamada contra os escopos atuais da chave.
</Note>

### Interruptores no nível do workspace

Mesmo com o escopo correto, dois interruptores do workspace precisam estar ligados:

| Interruptor | Desliga |
|-------------|---------|
| `mcp.writes.enabled` | Todas as ferramentas de escrita deste workspace. |
| `mcp.execute.enabled` | O `run_agent` deste workspace. |

Esses interruptores são um portão **independente**: ter o escopo certo na chave não basta enquanto o
interruptor estiver desligado. As duas recusas têm textos diferentes, e isso indica qual delas corrigir:

| Recusa | O que significa |
|--------|-----------------|
| `-32401 Insufficient scope`, com `data.required` informando o escopo que faltou | A chave não carrega esse escopo. Edite os escopos da chave. |
| `Tool execution failed: feature_disabled: mcp.writes.enabled is off for this workspace` (ou `mcp.execute.enabled`) | Os escopos da chave estão certos — o interruptor do workspace está desligado. Ligue o interruptor. |

Em qualquer um dos casos, a correção está no mesmo lugar: **Settings → MCP Tokens**.

Execuções iniciadas via MCP são cobradas e auditadas no **dono da chave** que as iniciou, e o nome da
chave/cliente que disparou aparece no histórico de execuções do agente.

## Perguntas frequentes

<AccordionGroup>
  <Accordion title="Qual método devo usar?">
    Se o seu cliente é Claude Desktop ou Claude.ai, você precisa usar OAuth. Para serviços de backend, a CLI ou o n8n, use um service token. Cursor e Claude Code podem usar qualquer um dos dois — OAuth é o mais simples se você consegue abrir um navegador.
  </Accordion>
  <Accordion title="Posso ter múltiplos service tokens para o mesmo workspace?">
    Sim — cada token é independente. Você pode ter um token por cliente (ex.: um para n8n, outro para um serviço de backend) e revogá-los individualmente em [**Settings → MCP Tokens**](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens).
  </Accordion>
  <Accordion title="O service token expira?">
    Service tokens não expiram automaticamente. Eles permanecem válidos até serem revogados. Recomendamos revogar tokens que você não usa mais.
  </Accordion>
  <Accordion title="Posso usar minha API key comum do FluxPrompt no lugar?">
    Não. O servidor MCP usa um sistema de autenticação separado. Sua API key comum não funcionará.
  </Accordion>
  <Accordion title="O que o servidor MCP enxerga do meu workspace?">
    Ele vê os mesmos agentes e estrutura que o usuário autenticado consegue ver dentro da interface do FluxPrompt. Ele não tem acesso a credenciais, faturamento ou gerenciamento de usuários.
  </Accordion>
  <Accordion title="Liberei write para alguém, mas o cliente dela continua só com read">
    Verifique nesta ordem:
    1. **Os interruptores do workspace.** `mcp.writes.enabled` e `mcp.execute.enabled` são um portão independente dos escopos da chave — uma chave que carrega `write` continua sendo recusada enquanto o interruptor estiver desligado. A recusa do interruptor diz `Tool execution failed: feature_disabled: ...`, não `Insufficient scope`.
    2. **Dê alguns segundos.** O servidor MCP mantém as chaves resolvidas em cache por `MCP_TOKEN_CACHE_TTL` segundos (10 por padrão), então um escopo recém-adicionado pode levar esse tempo para valer. Tente de novo depois de ~10 segundos ou reconecte o cliente.
    3. **Confirme que a mudança foi salva.** Reabra [**Settings → MCP Tokens**](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens) e verifique se a célula de escopos da chave mostra os escopos esperados.
    4. **Confirme que o cliente não está com uma sessão antiga.** Alguns clientes só releem as ferramentas e permissões disponíveis quando reconectam.
  </Accordion>
</AccordionGroup>
