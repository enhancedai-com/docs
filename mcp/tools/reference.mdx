## What Phase 2 adds

Phase 1 exposed three read-only tools. Phase 2 exposes **28**: the full read, authoring, versioning and execution surface, so an MCP client can build and run an agent end to end without opening the builder.

## Scopes

A token carries one or more scopes. Every tool below states the scope it needs; a call without it is refused with `-32401` and `data.required` naming the missing scope.

| Scope | Grants |
|---|---|
| `read` | Listing and inspecting agents, folders, versions and node types |
| `write` | Creating and editing agents, folders, nodes, edges and versions |
| `execute` | Starting runs, reading run results, cancelling runs |

<Note>
Scopes are flat and per workspace. `execute` covers both starting a run and reading its output, so a client that only needs to inspect results must be trusted to start them too.
</Note>

## Rules that apply to every tool

### Dry-run is the default for anything that writes

Every mutating tool takes `dryRun`, and it defaults to **true**. A dry run reports what would change and applies nothing. To apply, send `dryRun: false` **and** an `idempotencyKey`.

`idempotencyKey` is scoped to (workspace, tool, key), so the same string is safe to reuse across different tools. A replay with the same key and payload returns the cached result instead of acting twice. Cached results expire after 24 hours.

### workspaceId

Required only when your authorization covers more than one workspace. Call `list_workspaces` to see what it covers.

### Pagination

`list_agents`, `list_folders` and `list_versions` return `{ items…, total }` and, when more results exist, a `nextCursor`. Pass it back as `cursor` with the **same** other arguments — a cursor is bound to the arguments that produced it.

### What a response tells you beyond the result

| Field | Meaning |
|---|---|
| `unknownArguments` | Arguments you sent that the tool does not declare. They were **ignored** — check them, since the tool did something other than what you asked. |
| `invalidEnumValues` | A node field whose value is outside the declared enum. The write was applied, but the executor will not recognise the value and the node will do nothing. |
| `missingRequiredFields` | On `check_agent_integrity`: a required node field left empty. |
| `conditionRouting` | On nodes that branch: which handles the scheduler can actually emit. |
| `placementAdjusted` | The server moved the node so it would not overlap another. |

### Errors

| Code | Meaning | `data` |
|---|---|---|
| `-32401` | Auth failure or insufficient scope | `reason` or `required` |
| `-32602` | Invalid params | `missing` (parameters you left out) or `invalid` |
| `-32005` | Kill switch on | — |
| `-32006` | Rate limited, or circuit open | `reason`, `retryAfterMs`, `hint` |
| `-32601` | Unknown method | — |
| `-32603` | Internal error | — |

## The tools

### Discovery — no scope required

| Tool | Purpose |
|---|---|
| `list_workspaces` | The workspaces this authorization covers, with their scopes. Call it first when a token spans more than one. |
| `list_node_types` | The node catalogue: type, label, category, description. No schemas — call `get_node_type` for those. |

### Read — `read`

| Tool | Purpose |
|---|---|
| `list_agents` | Agents in the workspace, paginated. Filter by `search`, `folderId` or `folderName`. |
| `get_agent` | One agent with its nodes and edges. `includeNodes: false` returns metadata only. |
| `list_folders` | Folders, with `scope` (`space`/`personal`) and `spaceName` — a workspace routinely holds several folders with the same name. |
| `list_versions` | Version history of an agent, with `isDeployed` and `isStaging`. |
| `get_node_type` | One node type's `inputSchema`, `outputSchema` and `handles`. **Read this before authoring a node** — enum values and companion fields come from here. |
| `list_ai_models` | Models available to the workspace, with provider and `modelType`. |
| `check_agent_integrity` | Whether the flow can actually run: missing entry point, edges that would not render, companion arrays left empty, unreachable nodes. |

### Authoring — `write`

| Tool | Purpose |
|---|---|
| `create_folder` | Create a folder. |
| `rename_folder` · `remove_folder` | Rename or delete one. |
| `create_agent` | Create an agent inside a folder. `empty: true` starts from a blank canvas — recommended when you will add the nodes yourself. |
| `update_agent` · `remove_agent` | Rename or delete an agent. |
| `move_agent` | Move an agent into another folder. `targetFolderId` must name a folder; moving to the root is refused. |
| `add_node` · `update_node` · `remove_node` | Add, patch or delete a node. `update_node` merges `patch.data` one level deep, so omitted keys are preserved. |
| `connect_nodes` · `disconnect_nodes` | Wire or unwire two nodes. Called without handles, `connect_nodes` creates the execution edge, the data edge **and** the companion reference in one call. |
| `create_version` | Snapshot the working copy as a version. |
| `publish_version` | Deploy a version **to production**. There is no staging target. |

### Execution — `execute`

| Tool | Purpose |
|---|---|
| `run_agent` | Start a run. Returns a `runId`. |
| `get_run_status` | Status, tokens, cost, duration, error. **A `completed` run is not evidence that a node produced anything.** |
| `get_run_nodes` | Per-node state and output preview for a run. |
| `get_node_output` | One node's output. Secrets are redacted; large outputs are truncated and say so. |
| `cancel_run` | Request cancellation of a running agent. |

## Authoring an agent that actually runs

The order matters, and each step exists because skipping it produces a flow that saves and then does nothing:

<Steps>
  <Step title="Read the node's contract">
    `get_node_type` for every type you will use. Take enum values **verbatim** — an unrecognised value is reported in `invalidEnumValues` and makes the node a no-op.
  </Step>
  <Step title="Create the container">
    `create_folder`, then `create_agent` with `empty: true`.
  </Step>
  <Step title="Add a globalStarter">
    Its id must contain the literal `flow-global-starter`. The engine finds the flow's entry by matching that substring in the id — any other id saves and the flow never starts.
  </Step>
  <Step title="Add the nodes, then connect them">
    Call `connect_nodes` without handles and let it wire the execution edge, the data edge and the companion reference together.
  </Step>
  <Step title="Gate before running">
    `check_agent_integrity` must return `ok: true`.
  </Step>
  <Step title="Run and verify">
    `run_agent`, then `get_run_nodes` — not just `get_run_status`.
  </Step>
</Steps>

## Node types that produce nothing during a run

Eleven types are resolved by the builder, which calls the provider from the browser. Authored into a flow they report `completed` and store only their own configuration: `imageReaderNode`, `animationNode`, `commandMusicNode`, `storedDataCaller`, `deepRefNode`, `documentSummarizer`, `webAmazon`, `webTrends`, `usCensusNode`, `secApiNode`, `hubSpotCRM`.

Their descriptions carry a `RUNTIME BEHAVIOUR` warning. Do not wire one as a step another node reads from.
