## Description

Agents live inside folders, so creating an agent starts with a folder. All tools on this page follow
the shared write conventions — [dry-run by default, `idempotencyKey` to apply](/mcp/tools/writing-safely).

## `create_folder`

Creates a folder in the workspace.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Folder name. |
| `dryRun` | boolean | No | Default `true` — nothing is created. |
| `idempotencyKey` | string | Yes when `dryRun:false` | Replay-safe key. |

```json
{ "dryRun": false, "applied": true, "folder": { "id": "30be…", "name": "Sales agents" } }
```

## `create_agent`

Creates an agent (flow) inside a folder.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Agent name. |
| `folderId` | string (UUID) | Yes | Destination folder — from `create_folder` or `list_folders`. |
| `empty` | boolean | No | `true` starts with a blank canvas. Otherwise a starter template is applied. |
| `type` | string | No | `"agent"` (default) or `"chat"`. |
| `dryRun` / `idempotencyKey` | | | See [writing safely](/mcp/tools/writing-safely). |

```json
{ "dryRun": false, "applied": true, "agent": { "id": "d2c2…", "name": "Lead Scorer" } }
```

<Tip>
  Pass `empty: true` whenever you intend to build the flow yourself with `add_node`. Without it you
  inherit the starter template and end up with duplicate nodes alongside the ones you add.
</Tip>

## `list_folders`

Returns a page of folders plus `total`, and `nextCursor` when more results exist. Pass `nextCursor`
back as `cursor` for the next page. Treat cursors as opaque — never parse or build one, and never
pass a cursor from a different tool. Folders come back in the order the product displays them.

| Field | Type | Description |
|-------|------|-------------|
| `id` | string (UUID) | Pass this to `create_agent`, `move_agent` or `list_agents`. |
| `name` | string | Display name. **Not unique** — see below. |
| `parentId` | string (UUID) \| null | Parent folder, or `null` at the root. |
| `agentCount` | number | Agents directly inside. Matches `list_agents({ folderId })`'s `total`. |
| `scope` | `"space"` \| `"personal"` | Whether the folder belongs to a space or to a member personally. |
| `spaceId` | string (UUID) \| null | The owning space, when `scope` is `"space"`. |
| `spaceName` | string \| null | That space's name, for display. |
| `createdAt` | ISO 8601 \| null | When the folder was created — the tiebreaker when scope and space match too. |

### Two folders can share a name

This is by design, not corruption. Every member gets personal folders and every space gets its own,
and FluxPrompt seeds the same starter names into both — so a workspace commonly holds two folders
called `Chatbot` and two called `Shared`.

Use `scope` and `spaceName` to tell them apart, and **say which one you acted on** when you report
back: "added it to the *Design* space's `Chatbot`" rather than just "added it to `Chatbot`".

Nothing stops two folders in the **same** scope from sharing a name either — `create_folder` accepts a
name that is already taken. When `scope` and `spaceName` match, fall back to `createdAt`; the `id` is the
only field guaranteed to differ.

<Tip>
  You can still work from a name. `list_agents` accepts `folderName` and resolves it whenever exactly
  one folder carries it; if several match it fails with `folder_name_ambiguous` and lists the
  candidates. For everything else, pass the `id`. When a user's wording is ambiguous, ask — do not
  pick the first match.
</Tip>

## `list_agents`

Returns the agents in the workspace your token can reach. Each item carries the agent's id, name, description, node count, visibility and **which folder it lives in**, so you can tell where an agent sits without a second call.

### Input

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `folderId` | string (UUID) | No | List only the agents directly inside this folder. Get the id from [`list_folders`](/mcp/tools/agents-and-folders). Takes precedence over `folderName`. |
| `folderName` | string | No | Select the folder by name, matched case-insensitively. Works whenever exactly one folder carries that name. Ignored when `folderId` is given. |
| `search` | string | No | Case-insensitive substring filter on the agent name. |
| `cursor` | string | No | Opaque cursor from a previous response's `nextCursor`. Omit for the first page. |

Calling `list_agents` with no input returns the first page of every agent in the workspace.

<Note>
  Page size is decided by the server (50). There is no `limit` or `offset` parameter — see [Pagination](#pagination).
</Note>

### Output

```json
{
  "agents": [
    {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "name": "Lead Scorer",
      "description": "Scores inbound leads based on company size and tech stack",
      "updatedAt": "2026-05-31T14:22:00Z",
      "nodeCount": 12,
      "isPublic": false,
      "folderId": "3023e5f4-9099-4a56-bc28-538eb517a47f",
      "folderName": "Tasks"
    },
    {
      "id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "name": "Invoice Parser",
      "description": null,
      "updatedAt": "2026-06-01T09:45:00Z",
      "nodeCount": 7,
      "isPublic": true,
      "folderId": null,
      "folderName": null
    }
  ],
  "total": 19,
  "nextCursor": "NTAuX2FJUkY2V2EyNA"
}
```

#### Output fields

| Field | Type | Description |
|-------|------|-------------|
| `agents[].id` | string (UUID) | Unique identifier. Use this with `get_agent`. |
| `agents[].name` | string | Agent display name as shown in the FluxPrompt UI. |
| `agents[].description` | string \| null | Agent description, or `null` if none is set. |
| `agents[].updatedAt` | ISO 8601 string | When the agent was last modified. |
| `agents[].nodeCount` | number | Number of nodes in the agent's working copy. |
| `agents[].isPublic` | boolean | Whether the agent has a public-facing endpoint. |
| `agents[].folderId` | string (UUID) \| null | The folder the agent lives in. |
| `agents[].folderName` | string \| null | That folder's name, for display. |
| `total` | number | Total agents matching the query, so you know how much remains. |
| `nextCursor` | string | Present **only** when more results exist. Absent on the last page. |

Agents come back in the order the product displays them, so a listing matches what the user sees on their canvas.

### Scoping to a folder

Two ways to name the folder:

```
list_agents({ folderId: "3023e5f4-9099-4a56-bc28-538eb517a47f" })
list_agents({ folderName: "Tasks" })
```

`folderName` is the convenient path when you only know what the user called it. It resolves whenever **exactly one** folder carries that name:

| Matches | Result |
|---|---|
| Exactly one | Resolved — the listing is scoped to that folder. |
| None | `folder_not_found` |
| Several | `folder_name_ambiguous`, listing the candidate ids with their scope |

<Warning>
  **Same-named folders are normal in FluxPrompt, not a mistake.** A folder belongs either to a **space** (shared with the team) or to a **member personally**, and the same starter names — `Chatbot`, `Shared` — are created in both. A workspace can easily hold two folders called `Chatbot`.

  When `folderName` is ambiguous the error names each candidate with its scope, for example `folder-a (personal), folder-b (space "Design")`. Pick one and pass it as `folderId`, or ask the user which they meant — do not guess.
</Warning>

A `folderId` from another workspace is rejected with `folder_not_found` rather than returning an empty page, so an empty result always means "this folder has no agents" and never "you asked for the wrong folder".

### Pagination

`list_agents` uses **cursor pagination**. Read `nextCursor` from the response and pass it back as `cursor`. When `nextCursor` is absent, you have the last page.

```
Call 1: list_agents({ folderId: "3023e…" })                    → 50 agents, nextCursor: "NTAu…"
Call 2: list_agents({ folderId: "3023e…", cursor: "NTAu…" })    → next 50,   nextCursor: "MTAw…"
Call 3: list_agents({ folderId: "3023e…", cursor: "MTAw…" })    → remainder, no nextCursor
```

<Warning>
  **A cursor is bound to the arguments that produced it.** Resend the *same* `folderId`, `folderName` and `search` alongside it. If you change a filter — or drop it — the cursor is rejected with an error saying the query changed; start again without a cursor.

  This is deliberate. A cursor is an opaque position in one specific result set, so reusing it against a different filter would silently skip or repeat agents rather than fail. Never parse, build, or edit a cursor, and never carry one between tools.
</Warning>

## `get_agent`

Fetches one agent. Use it after `list_agents` to read the nodes and edges you are about to change.

### Input

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | The agent's unique identifier. Get this from `list_agents`. |
| `includeNodes` | boolean | No | Whether to include the `nodes` and `edges` arrays. Default: `true`. Set to `false` for a lightweight, metadata-only response. |

### Output

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "name": "Lead Scorer",
  "description": "Scores inbound leads based on company size and tech stack",
  "updatedAt": "2026-05-31T14:22:00Z",
  "nodeCount": 2,
  "isPublic": false,
  "nodes": [
    {
      "id": "flow-global-starter_0.689",
      "type": "globalStarter",
      "data": { "myId": "flow-global-starter_0.689", "label": "Flow Global Node" },
      "position": { "x": 250, "y": 25 },
      "width": 402,
      "height": 206
    },
    {
      "id": "commandTextNode_0.628",
      "type": "commandTextNode",
      "data": { "label": "Score generator", "model": "claude-3-5-sonnet" },
      "position": { "x": 400, "y": 200 },
      "width": 320,
      "height": 180
    }
  ],
  "edges": [
    {
      "id": "reactflow__edge-flow-global-starter_0.689a-commandTextNode_0.628input",
      "source": "flow-global-starter_0.689",
      "sourceHandle": "a",
      "target": "commandTextNode_0.628",
      "targetHandle": "input",
      "type": "custom",
      "style": { "stroke": "#6e75ff", "strokeWidth": 1 },
      "animated": true,
      "markerEnd": { "type": "arrowclosed", "color": "red", "width": 25, "height": 25 }
    }
  ]
}
```

When `includeNodes` is `false`, the `nodes` and `edges` arrays are omitted and only the metadata fields are returned.

#### Output fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Agent UUID. |
| `name` | string | Agent display name. |
| `description` | string \| null | Agent description. |
| `updatedAt` | ISO 8601 string | Last modification time. |
| `nodeCount` | number | Number of nodes in the agent's current version. |
| `isPublic` | boolean | Whether the agent has a public endpoint. |
| `nodes` | array | All nodes in the agent (omitted when `includeNodes` is `false`). See below. |
| `edges` | array | All connections between nodes (omitted when `includeNodes` is `false`). |

#### Node fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Node ID (unique within this agent). |
| `type` | string | Node type (e.g. `globalStarter`, `commandTextNode`, `conditionNode`). See `list_node_types` for the full list. |
| `data` | object | Node-specific configuration and display data (includes the node's `label`). Shape depends on `type`. |
| `position` | object | `{ x, y }` coordinates on the canvas. |
| `width` | number | Node width on the canvas. |
| `height` | number | Node height on the canvas. |

#### Edge fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Edge ID. |
| `source` | string | ID of the source node. |
| `sourceHandle` | string | Which output handle on the source node this edge leaves from. |
| `target` | string | ID of the target node. |
| `targetHandle` | string | Which input handle on the target node this edge connects to. |
| `type` | string | Edge renderer type (e.g. `custom`). |
| `style` | object | Visual styling (stroke color, width). |
| `animated` | boolean | Whether the edge is animated on the canvas. |
| `markerEnd` | object | Arrowhead marker configuration. |

### Error: agent not found

If the `agentId` does not exist in your workspace, the call returns a **tool error** (not a protocol-level error) — a successful JSON-RPC response whose `result` has `isError: true`:

```json
{
  "result": {
    "content": [
      { "type": "text", "text": "Agent \"a1b2c3d4-...\" not found in this workspace." }
    ],
    "isError": true
  }
}
```

This is also returned if the agent exists but belongs to a different workspace. For security, the response does not reveal whether the agent exists outside your workspace.

## `update_agent`

Updates an agent's metadata. Currently only its `name`.

| Parameter | Type | Required |
|-----------|------|----------|
| `agentId` | string (UUID) | Yes |
| `name` | string | Yes |

Accepts `expectedVersion` but **not** `versionId` — an agent's name is not version-scoped.

## `move_agent`

Moves an agent to another folder.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Agent to move. |
| `targetFolderId` | string \| null | No | Destination folder, or `null` to move it to the root. |

## `rename_folder`

| Parameter | Type | Required |
|-----------|------|----------|
| `folderId` | string (UUID) | Yes |
| `name` | string | Yes |

## `remove_agent` / `remove_folder`

Delete an agent or a folder. Both are destructive and both default to dry-run.

<Warning>
  Deleting is not undone by a version: versions belong to the agent, so removing the agent removes
  its history too. Inspect the dry-run diff before applying.
</Warning>

## Example prompts

- *"Create a folder called Sales agents and an empty agent called Lead Scorer inside it"*
- *"Rename the folder 30be… to Archive"*
- *"Move my Lead Scorer agent to the root"*
