## Description

Agents live inside folders, so creating an agent starts with a folder. All tools on this page follow
the shared write conventions — [dry-run by default, `idempotencyKey` to apply](/mcp/tools/writing-safely).

## `create_folder`

Creates a folder in the workspace.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Folder name. |
| `dryRun` | boolean | No | Default `true` — nothing is created. |
| `idempotencyKey` | string | Yes when `dryRun:false` | Replay-safe key. |

```json
{ "dryRun": false, "applied": true, "folder": { "id": "30be…", "name": "Sales agents" } }
```

## `create_agent`

Creates an agent (flow) inside a folder.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Agent name. |
| `folderId` | string (UUID) | Yes | Destination folder — from `create_folder` or `list_folders`. |
| `empty` | boolean | No | `true` starts with a blank canvas. Otherwise a starter template is applied. |
| `type` | string | No | `"agent"` (default) or `"chat"`. |
| `dryRun` / `idempotencyKey` | | | See [writing safely](/mcp/tools/writing-safely). |

```json
{ "dryRun": false, "applied": true, "agent": { "id": "d2c2…", "name": "Lead Scorer" } }
```

<Tip>
  Pass `empty: true` whenever you intend to build the flow yourself with `add_node`. Without it you
  inherit the starter template and end up with duplicate nodes alongside the ones you add.
</Tip>

## `list_folders`

Returns a page of folders plus `total`, and `nextCursor` when more results exist. Pass `nextCursor`
back as `cursor` for the next page. Treat cursors as opaque — never parse or build one, and never
pass a cursor from a different tool.

## `update_agent`

Updates an agent's metadata. Currently only its `name`.

| Parameter | Type | Required |
|-----------|------|----------|
| `agentId` | string (UUID) | Yes |
| `name` | string | Yes |

Accepts `expectedVersion` but **not** `versionId` — an agent's name is not version-scoped.

## `move_agent`

Moves an agent to another folder.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Agent to move. |
| `targetFolderId` | string \| null | No | Destination folder, or `null` to move it to the root. |

## `rename_folder`

| Parameter | Type | Required |
|-----------|------|----------|
| `folderId` | string (UUID) | Yes |
| `name` | string | Yes |

## `remove_agent` / `remove_folder`

Delete an agent or a folder. Both are destructive and both default to dry-run.

<Warning>
  Deleting is not undone by a version: versions belong to the agent, so removing the agent removes
  its history too. Inspect the dry-run diff before applying.
</Warning>

## Example prompts

- *"Create a folder called Sales agents and an empty agent called Lead Scorer inside it"*
- *"Rename the folder 30be… to Archive"*
- *"Move my Lead Scorer agent to the root"*
