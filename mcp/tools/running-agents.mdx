## Description

Running is asynchronous: `run_agent` returns a `runId` immediately and you poll `get_run_status` for
the outcome. These tools need the `execute` scope, and the workspace toggle `mcp.execute.enabled`
must be on — see [writing safely](/mcp/tools/writing-safely).

## `run_agent`

Dispatches a run.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `agentId` | string (UUID) | Yes | Agent to run. |
| `variableInputs` | array | No | Inputs for the run: `[{ inputId, inputText, … }]`. |
| `sessionId` | string | No | Session id, for session-scoped memory. |
| `versionId` | string | No | Run that specific snapshot, whatever is currently deployed. |
| `dryRun` | boolean | No | Default `true` — validate only. |
| `idempotencyKey` | string | Yes when `dryRun:false` | Prevents a duplicate run on retry. |

**Dry-run here means validate-only:** it checks the workspace flag, your scope and your remaining
quota, and resolves the inputs, without dispatching anything.

```json
{ "dryRun": false, "dispatched": true, "runId": "c7f0…", "quotaRemaining": 48 }
```

### Which version runs

| `versionId` | What runs |
|-------------|-----------|
| Provided | That snapshot, regardless of what is deployed. |
| Omitted | The currently deployed version, if the agent has one (version control enabled **and** a published version). Otherwise the live working copy. |

<Tip>
  `idempotencyKey` matters more here than anywhere else: without it a retried request bills a second
  run. Derive the key from the intent of the run, not from the timestamp of the attempt.
</Tip>

## `get_run_status`

Polls a run.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `runId` | string | Yes | The id returned by `run_agent`. |

Returns:

| Field | Type | Description |
|-------|------|-------------|
| `runId` | string | The run being reported. |
| `status` | `"pending"` \| `"in_progress"` \| `"completed"` \| `"error"` | Current state of the run. `pending` is queued and not started; `completed` and `error` are final. A run you cancelled reports `error` with the message `Run cancelled`. |
| `tokens` | number | FluxCredits consumed — a decimal amount of credits, not a provider token count. |
| `cost` | number | Cost attributed to the run. |
| `durationMs` | number | Wall-clock duration. |
| `error` | string \| null | Failure reason, or `null` when there is none. |
| `triggeredBy` | string \| null | Name of the key or client that started the run, or `null` when it cannot be resolved. |

Poll at a sensible interval — a run that calls several AI models takes seconds to minutes, and every
poll counts against your rate limit (60 requests/minute, 5 000/day per key).

## `get_run_nodes`

Returns one entry per node that started executing in a run. Use this instead of trusting the run's
aggregate status: a run reports `"completed"` as long as it finished, even when a node never ran.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `runId` | string | Yes | The id returned by `run_agent`. |
| `limit` | number | No | Page size. Default 50, capped at 200. |

Returns `runId`, `versionId` (the FlowVersion the run targeted, or `null` for the working copy),
`total` (the true count of nodes that started, not capped by the page size), `truncated` (boolean —
more nodes exist beyond this page), `suspects` (count of entries whose `suspect` is non-null), and a
`nodes` array:

| Field | Type | Description |
|-------|------|-------------|
| `nodeId` | string | Node id — pass to `get_node_output`. |
| `type` | string \| null | Node type. |
| `state` | `"running"` \| `"succeeded"` \| `"failed"` | |
| `startedAt` / `finishedAt` | ISO 8601 / ISO 8601 \| null | |
| `error` | string \| null | |
| `outputBytes` | number \| null | Size of the stored output. |
| `outputPreview` | string \| null | First 200 characters, redacted before truncation. |
| `outputRedacted` | boolean | `true` when a secret pattern was removed from the preview. |
| `outputExpired` | boolean | `true` when retention already discarded the payload. |
| `suspect` | `null` \| `{ code, consumers, hint }` | Heuristic only — set when a node succeeded with an empty output while a downstream node was waiting on it through a data edge. It is always `null` when the run graph could not be loaded, rather than guessed. |

<Warning>
  **Overlapping runs of the same agent can show each other's nodes.** Node executions are matched to
  a run by the agent and the run's time window (start to finish, with a minute of slack), because
  nodes executed by the Temporal worker carry no run id of their own. Rows that do carry the run id
  are matched exactly, but two runs of the **same agent** that overlap in time cannot be told apart
  — the same node executions appear in both. A single run stays exact.
</Warning>

<Note>
  An absent node is still not proof it never ran: it may have been pruned by a condition branch, be
  unreachable from the starter, or have been skipped because an earlier node failed — this tool
  cannot tell those cases apart. Nodes inside a `libraryNode` or `flowCaller` sub-flow belong to
  their own run and are not listed here. At most 200 executions are read per run.
</Note>

Use `outputPreview` to skim, not to read the result — call `get_node_output` for the full value.

## `get_node_output`

Returns what a single node produced in a run. Call `get_run_nodes` first to see which nodes this tool
can reach.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `runId` | string | Yes | The id returned by `run_agent`. |
| `nodeId` | string | Yes | Node id, as it appears in `get_run_nodes`. |

Returns `runId`, `nodeId`, `type`, `state`, `outputType` (which field the value came from), `output`
(the node's scalar result — redacted first, then truncated at 20 000 characters), `truncated`,
`totalBytes`, `redacted` (a secret pattern or sensitive key was removed), `outputExpired`, `error`
and `finishedAt`.

<Warning>
  **An error here means no execution row for that node was found in this run's window** — the node
  never started, was pruned by a condition branch, or was skipped because an earlier node failed.
  The same overlap caveat as `get_run_nodes` applies: two runs of the same agent that overlap in
  time share node executions. Only the scalar output is returned, deliberately — the stored node
  object also holds resolved prompts and credential fields.
</Warning>

## `cancel_run`

Requests cancellation of a run that is still in flight.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `runId` | string | Yes | The id returned by `run_agent`. |
| `dryRun` | boolean | No | Default `false` — cancels immediately. Set `true` to check whether the run could be cancelled, without cancelling it. |
| `idempotencyKey` | string | No | Accepted, but not used: the server does not cache or replay a cancel. See the note below. |

```json
{ "runId": "c7f0…", "cancelled": true, "reason": "cancelled" }
```

| Field | Type | Description |
|-------|------|-------------|
| `runId` | string | The run you asked about. |
| `cancelled` | boolean | `true` only when the run was actually cancelled. |
| `reason` | `"cancelled"` \| `"cancel_unsupported"` \| `"dry_run"` | `cancelled` — the run was stopped. `dry_run` — you passed `dryRun: true`; nothing was cancelled. `cancel_unsupported` — there was nothing to cancel: the run already finished, is not tracked any more, or is not one this workspace owns. |

The response carries no `dryRun` or `applied` fields, unlike the other write tools.

A run still queued is removed from the queue; a run already processing is cancelled through its
workflow, so "processing" is not too late.

<Warning>
  **`cancel_run` is the one write tool that does not default to dry-run.** Every other write tool
  defaults to `dryRun: true`; `cancel_run` defaults to `dryRun: false` and cancels immediately. See
  [Writing safely](/mcp/tools/writing-safely#dry-run-is-the-default).
</Warning>

<Note>
  **`cancel_run` skips the write gate and the idempotency cache.** Unlike the other write tools it
  needs only the `execute` scope — the `mcp.execute.enabled` switch is not checked — and an
  `idempotencyKey` changes nothing. A retry just asks again: it is harmless, because a run that
  already stopped answers `cancel_unsupported`.
</Note>

Work already completed is not rolled back — cancelling stops the run going forward, it does not undo
side effects a node already produced (a sent email stays sent).

## Run attribution

Runs started through MCP are billed and audited against the **owner of the key that started them**,
and the triggering key/client name shows up in the agent's execution history — so a run dispatched
from an AI client is traceable back to it.
