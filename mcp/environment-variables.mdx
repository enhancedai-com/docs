## Cross-repo gotcha

`MCP_INTERNAL_SECRET` and `MCP_OAUTH_CONSENT_SECRET` must be identical to the values in `back` — same SSM param in every environment, or MCP calls 500 / OAuth consent fails silently.

## CI/CD

Same runtime-injection pattern as `back`/`worker` — vars live in the ECS task definition (SSM-backed), not baked at build time. Only `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` are needed as repo secrets (confirmed present).

**`production` lags behind.** `main` and `staging` carry the current code and the full CI/CD workflow
set (`cicd_dev.yml`, `cicd_staging.yml`, `cicd_prod.yml`, `pr-review.yml`, `_test-gate.yml`).
`production` is still the Phase 0 scaffold commit: no CI/CD workflow, and an `.env.example` with older
names (`BACK_API_URL` instead of `BACK_BASE_URL`, `MCP_CIRCUIT_*` instead of `MCP_CB_*`). Don't use
`production` as a reference for current env var names.
