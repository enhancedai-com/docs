## Fixed during this audit

The old `.env.example`/`docker-compose.yml` had names that didn't match what the code actually reads — those configs were silent no-ops:

- `BACK_API_URL` → code reads `BACK_BASE_URL`
- `MCP_CIRCUIT_ERROR_RATE_THRESHOLD` / `MCP_CIRCUIT_WINDOW_SECONDS` / `MCP_CIRCUIT_COOLDOWN_SECONDS` → code reads `MCP_CB_ERROR_THRESHOLD` / `MCP_CB_WINDOW_MS` / `MCP_CB_COOLDOWN_MS` (also note: ms, not seconds)
- `DD_API_KEY` / `DD_SITE` / `DD_AUDIT_INDEX` → code reads `DATADOG_API_KEY` (`DD_SITE`/`DD_AUDIT_INDEX` aren't read anywhere)

All renamed to match the code in this pass.

## Cross-repo gotcha

`MCP_INTERNAL_SECRET` and `MCP_OAUTH_CONSENT_SECRET` must be identical to the values in `back` — same SSM param in every environment, or MCP calls 500 / OAuth consent fails silently.

## CI/CD

Same runtime-injection pattern as `back`/`worker` — vars live in the ECS task definition (SSM-backed), not baked at build time. Only `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` are needed as repo secrets (confirmed present).

**Gap:** the CI/CD workflows (`cicd_dev.yml`, `cicd_staging.yml`, `cicd_prod.yml`) only exist on the `staging` branch. `production` is still the Phase 0 scaffold commit — there's no deploy pipeline there yet.
