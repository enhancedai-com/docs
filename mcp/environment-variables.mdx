26 env vars in `mcp-server/.env.example`. Legend: **Required** = app breaks or a feature silently fails without it, **Optional** = has a default/fallback in code.

| Var | Required? | Purpose |
|---|---|---|
| PORT | Optional | HTTP port (default 3100) |
| NODE_ENV | Optional | Node environment (passthrough, not read in code) |
| MCP_HTTP_LOG | Optional | verbose HTTP request logging for `/oauth`, `/mcp` and `/.well-known` paths. Enabled only by the exact value `on`; any other value, including `true` or `1`, leaves it off |
| MCP_PUBLIC_URL | Optional | public origin of the server, without `/mcp` (OAuth issuer and metadata, and the `WWW-Authenticate` header). Default `http://localhost:3100` |
| MCP_FRONT_CONSENT_URL | Optional | the front's consent page, code default `http://localhost:3000/mcp-authorize.html` (the local front); set it explicitly in every other environment |
| MCP_OAUTH_CONSENT_SECRET | Required | validates consent signature — must match `back`'s value |
| MCP_OAUTH_TOKEN_TTL | Optional | Access-token lifetime in seconds. Empty or `0` (the default) issues tokens that never expire, because there is no refresh grant yet |
| MCP_DCR_CLIENT_TTL | Optional | Dynamic Client Registration TTL in seconds (default 90 days, `7776000`) |
| MCP_TOKEN_CACHE_TTL | Optional | token resolver cache TTL in seconds (default 10). Caps how long a revoked key can still be accepted at the edge, so keep it well under the 30s revocation SLA. |
| BACK_BASE_URL | Optional | `back` base URL (code default `http://localhost:3001`). Use `host.docker.internal` from Docker |
| MCP_INTERNAL_SECRET | Required | secret to call `back` — must match `back`'s value |
| MCP_BACK_RETRY_MAX | Optional | max attempts for `back` calls (default 3) |
| MCP_BACK_RETRY_BASE_MS | Optional | retry backoff base (ms) (default 200) |
| MCP_MODELS_TTL_MS | Optional | AI model catalogue cache TTL in ms (default 120000) |
| MCP_NODE_TYPES_TTL_MS | Optional | node type catalogue cache TTL in ms (default 600000) |
| MCP_TASK_TTL_MS | Optional | how long a task result stays retrievable, in ms (default 3600000) |
| MCP_RATE_LIMIT_PER_MINUTE | Optional | rate limit per minute (default 60) |
| MCP_RATE_LIMIT_PER_DAY | Optional | rate limit per day (default 5000) |
| MCP_KILL_SWITCH | Optional | global on/off switch. Only the exact value `on` disables the server (calls answer `-32005 Service disabled`); anything else, or unset, keeps it enabled |
| MCP_CB_WINDOW_MS | Optional | circuit breaker sampling window (default 60000) |
| MCP_CB_COOLDOWN_MS | Optional | circuit breaker cooldown (default 60000) |
| MCP_CB_ERROR_THRESHOLD | Optional | circuit breaker error rate threshold (default 0.5) |
| MCP_CB_MIN_SAMPLES | Optional | min samples before evaluating circuit (default 5) |
| DATADOG_API_KEY | Optional | Datadog audit log key |
| INSPECTOR_CLIENT_PORT | Optional | MCP Inspector UI port — currently inert; only read by the disabled Docker `inspector:` service, not by the `pnpm inspect` script actually used to run it (dev only) |
| INSPECTOR_PROXY_PORT | Optional | MCP Inspector proxy port — currently inert; only read by the disabled Docker `inspector:` service, not by the `pnpm inspect` script actually used to run it (dev only) |

## Cross-repo gotcha

`MCP_INTERNAL_SECRET` and `MCP_OAUTH_CONSENT_SECRET` must be identical to the values in `back` — same SSM param in every environment, or MCP calls 500 / OAuth consent fails silently.

## Related variables in `back`

The `back` side of the MCP integration has its own variables — notably `MCP_SERVER_INTERNAL_URL` and `MCP_RESOURCE_METADATA_URL`. They are documented in [Main API environment variables](/main-api/environment-variables); `MCP_INTERNAL_SECRET` and `MCP_OAUTH_CONSENT_SECRET` must match there. For a local OAuth setup, see [Local development](/mcp/connect/local-dev#local-oauth).

## CI/CD

Same runtime-injection pattern as `back`/`worker` — vars live in the ECS task definition (SSM-backed), not baked at build time. Only `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` are needed as repo secrets (confirmed present).

**`production` lags behind.** `main` and `staging` carry the current code and the full CI/CD workflow
set (`cicd_dev.yml`, `cicd_staging.yml`, `cicd_prod.yml`, `pr-review.yml`, `_test-gate.yml`).
`production` is still the Phase 0 scaffold commit: no CI/CD workflow, and an `.env.example` with older
names (`BACK_API_URL` instead of `BACK_BASE_URL`, `MCP_CIRCUIT_*` instead of `MCP_CB_*`). Don't use
`production` as a reference for current env var names.
