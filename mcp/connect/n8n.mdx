## What this enables

Inside n8n you can build workflows that automatically:

- Fetch the list of your FluxPrompt agents
- Inspect an agent's node structure
- Branch logic based on what agents exist

## Prerequisites

- n8n instance (cloud or self-hosted, v1.22+)
- A FluxPrompt workspace **service token** (see [Authentication](/mcp/authentication)) — generate one in [**Settings → MCP Keys**](https://app.fluxprompt.ai/dashboard-beta?settings=mcpTokens). A static service token is the recommended method for n8n.

## Step-by-step

<Steps>
  <Step title="Add an MCP Client Tool node">
    In your n8n workflow, click **+** to add a node. Search for **MCP Client Tool** and select it.
  </Step>
  <Step title="Configure the connection">
    In the node settings, set:

    | Field | Value |
    |-------|-------|
    | **Server URL** | `https://mcp.fluxprompt.ai/mcp` |
    | **Authentication** | Header Auth |
    | **Header Name** | `Authorization` |
    | **Header Value** | `Bearer YOUR_SERVICE_TOKEN` |

    Replace `YOUR_SERVICE_TOKEN` with your actual service token (starts with `mcp_`).
  </Step>
  <Step title="Choose the tool and parameters">
    In the **Tool** dropdown, select the FluxPrompt tool you want, for example:

    - `list_agents` — no parameters required; optional `search`, `folderId`, `folderName` and `cursor`
    - `get_agent` — requires `agentId` (the agent's UUID)
    - `list_node_types` — no parameters required

    Set any required parameters in the **Tool Parameters** section. The full list of tools and their parameters is in the [tool catalog](/mcp/tools/agents-and-folders); see [Tools and scopes](#tools-and-scopes) for what your key can call.
  </Step>
  <Step title="Test the node">
    Click **Execute node**. The output will contain the structured response from FluxPrompt.
  </Step>
</Steps>

## Example: list all agents and filter by name

This workflow lists all FluxPrompt agents and filters for ones whose name contains "Parser":

1. **MCP Client Tool** — calls `list_agents` with `search` set to `Parser`. The server filters by name (case-insensitive), so you don't need a Code node for a simple match.
2. **Pagination** — `list_agents` returns a page of up to 50 agents as `{ agents, total, nextCursor }`. `nextCursor` is present only when more results exist. To get the next page, call the tool again with `cursor` set to that `nextCursor` and the **same** `search`, `folderId` and `folderName`; loop until `nextCursor` is absent. A cursor is bound to the filters that produced it and is rejected if you change them.
3. **Code node** — combine the pages, for example `return $input.all().flatMap(item => item.json.agents)`.
4. **Whatever you need next** — send results to Slack, write to a spreadsheet, etc.

If you skip step 2, you only see the first 50 agents.

## Tools and scopes

n8n can call the full FluxPrompt tool catalog. Which tools it can use depends on the scopes on your key:

| Scope | What it unlocks | Catalog |
|-------|-----------------|---------|
| `read` | List and inspect agents, folders, versions, node types, models, integrations and voices | [Agents & folders](/mcp/tools/agents-and-folders), [Nodes & edges](/mcp/tools/nodes-and-edges), [Versioning](/mcp/tools/versioning) |
| `write` | Create and edit agents, folders, nodes and edges; snapshot and publish versions | [Writing safely](/mcp/tools/writing-safely), [Agents & folders](/mcp/tools/agents-and-folders), [Nodes & edges](/mcp/tools/nodes-and-edges), [Versioning](/mcp/tools/versioning) |
| `execute` | Run an agent, poll a run, cancel a run | [Running agents](/mcp/tools/running-agents) |

A tool your authorization does not cover is refused with `-32401 Insufficient scope`. Write and execute tools also need the matching workspace settings turned on — see [Authentication](/mcp/authentication#workspace-level-switches).
