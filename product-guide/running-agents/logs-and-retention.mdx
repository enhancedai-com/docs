## What it is

Every time an agent runs — from the editor, the API, a webhook, a schedule, a chatbot or an AI assistant
through the MCP — FluxPrompt records a **run log**: who started it, how, when, how long it took, what it cost,
and what each node received and produced.

**Log retention** decides how long those logs are kept, space by space. Logs older than the window are
deleted permanently.

## Who can use it

- **Logs**: Owners, Admins and Builders see the runs of the agents they can open. On a shared system
  agent you see only your own runs. Members with the **User** role do not have the **Logs** page.
- **Log retention**: organization admins. The organization owner sets the default for all spaces; an admin
  can change the spaces they administer.

## Find a run

<Steps>
  <Step title="Open Logs">
    Click **Logs** in the left sidebar to see runs across all your agents (the page is titled **Logging**).
    To see one agent's runs, open the agent and click its **Logs** tab.
  </Step>
  <Step title="Narrow the list">
    Search by name or process ID, or use the filters:

    | Filter | Options |
    |--------|---------|
    | Status | In Progress, Success, Failed, Cancelled |
    | User | Who started the run |
    | Date | Last 24h, Last 7 days, Last 30 days |
    | Duration | < 5s, 5s – 20s, > 20s |
    | Credits | 0 credits, < 1k, 1k – 5k, > 5k credits |
    | Space | The space of the agent |
    | Source | **Agent** (a full run) or **Node** (one node run from the editor) |
    | Trigger | **API**, **Webhook**, **Scheduled**, **Manual** |
  </Step>
  <Step title="Open the run">
    Click a row. The run page shows the status, duration, credits, cost, process ID, space and trigger, then
    one row per node with what it received and produced. Use **Copy JSON** to copy the run.
  </Step>
</Steps>

The list shows these columns: **Process ID**, **Source**, **Name**, **Trigger**, **Space**, **Status**,
**Started**, **Duration** and **Started by**.

<Note>
  The **Logs** page always shows the **last 30 days**, even when a space keeps its logs longer.
</Note>

## Set how long a space keeps its logs

<Steps>
  <Step title="Open Log Retention">
    Open **Settings** and choose **Log Retention**.
  </Step>
  <Step title="Pick a window for a space">
    In the table, find the space and choose a value under **Logs kept for**: the organization default,
    1, 3, 7, 15 or 30 days, or **Custom…** (any whole number of days, 1 or more).
  </Step>
  <Step title="Confirm">
    If the new window is shorter, a confirmation tells you how many logs will be deleted, for example
    **Delete 120 logs**. Deleted logs cannot be recovered. A longer window applies at once.
  </Step>
</Steps>

### Change the default for all spaces

The organization owner sees **Default for all spaces** at the top of the section. Spaces without their own
setting use it. When no default is set, logs are kept for **30 days**.

## What happens when logs expire

FluxPrompt cleans up logs every day:

| When | What happens |
|------|--------------|
| When you shorten a window | Logs older than the new window are deleted right away. |
| After 7 days | A run's node inputs and outputs are removed to save space. The run's status and result text stay. The node shows **I/O expired**, and the run page says **This run’s data is unavailable due to retention limits.** |
| After the space's window | The run's logs are deleted permanently. |
| Always | Only the latest 50 runs of each node are kept, whatever the window. |

## Limits

| Limit | Value |
|-------|-------|
| Shortest window | 1 day |
| Default window | 30 days, unless the owner sets another default |
| Logs page | Last 30 days |
| Node inputs and outputs | Kept for 7 days |
| Runs kept per node | Latest 50 |
| Rows per page in Logs | 15 |

## Troubleshooting

| Problem | What to check |
|---------|---------------|
| I do not see **Log Retention** in Settings | Only organization admins see it. |
| I do not see **Default for all spaces** | Only the organization owner sees and changes it. |
| **You are not an admin of this space** | You can only change spaces you administer. |
| A run older than 30 days is missing | The Logs page shows the last 30 days only. |
| A node shows **I/O expired** | Its inputs and outputs were removed after 7 days. The status and result text are still there. |
| I cannot find a run from another person | On a shared system agent you only see your own runs. |
| **No runs match your filters** | Clear the filters, or widen the date range. |
