## What is a rule

A `.md` file that documents a pattern the agent should follow. Claude Code loads rules automatically; you do not have to invoke them. They live in two places:

- **Workspace rules**, in the Workflow repo's `.claude/rules/`. `investigation.md`, `git-and-envs.md` and `prod-and-infra.md` always load; `back.md`, `front.md` and `worker.md` load when you touch that repo.
- **Repo rules**, in `<repo>/.claude/rules/` inside each product repo (`back/`, `front/`, `worker/`).

## When to write one

- A pattern was violated and had to be fixed in review.
- A gotcha took hours to debug.
- A convention is non-obvious from the code.

## Shape

```markdown
---
description: One-sentence summary. Starts with "Apply when..." so the agent knows the trigger.
---

# <Rule name>

## When this applies
<concrete scenario>

## What to do
<pattern>

## What NOT to do
<antipattern>

## Why
<reason, often linking to the incident that produced the rule>
```

## Real examples

- `.claude/rules/investigation.md` (Workflow repo)
- `front/.claude/rules/node-run-flush.md`
- `front/.claude/rules/react-query.md`
- `back/.claude/rules/code-standards.md`

## Rules vs skills vs hooks

- **Rule** — passive, auto-loaded guidance. Agent reads it; nothing enforces it.
- **Skill** — procedural, trigger-driven. Loaded when the task matches.
- **Hook** — code that runs before/after a tool call. Can block.

If you need enforcement, write a hook. If you need a procedure, write a skill. For patterns to follow, a rule is enough.
