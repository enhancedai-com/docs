The workspace root is the **Workflow** repo (`enhancedai-com/Workflow`), which holds the shared Claude Code tooling. The product repos are cloned inside it as separate git repositories, with these exact folder names, and the Workflow repo gitignores them.

## Product repos

| Folder | Repo | Role | Production branch |
|---|---|---|---|
| `back/` | Flux-Prompt | NestJS backend API | `main` |
| `front/` | Flux-Prompt-Frontend | React (Vite) frontend | `main` |
| `worker/` | Flux-Prompt-Worker | Temporal worker that executes flow nodes | `main` |
| `mcp/` | FluxPrompt-MCP | Public MCP server | `main` |
| `docs/` | docs | Mintlify docs (this site) | `main` |
| `memflux/` | MemFlux | Unified memory service | `main` |

`back`, `front`, `worker` and `mcp` use `develop` (dev), `staging`, and `main` (production). `docs` has only `main`. `memflux` has its own model (`main` plus `release/*`). See [Git workflow](/getting-started/git-workflow) for the full branch strategy.

Run git commands inside the folder of the repo you are changing.

## Workflow repo folders

- `CLAUDE.md`, `ONBOARDING.md`: workspace instructions and the setup guide.
- `.claude/`: shared Claude Code configuration: `agents/`, `skills/`, `rules/`, `hooks/`, `kb/`, `tasks/`, `output-styles/`, `settings.json`.
- `.mcp.json`: the MCP servers the workspace loads.
- `.env.example`: template for the workspace-root `.env` that the DB-tunnel skills read.
- `docker/`: the local stack (`docker/devdb/`: Postgres, Redis, Temporal, back and worker).
- `scripts/`: workspace scripts, such as `deploy-direct/`.
- `debug-playwright/`: scripted E2E runs against the deployed front.
- `guide/`: the offline workshop site.

See [Where things live](./where-things-live) for artifacts (skills, agents, rules, hooks, memory, guardrails).
