## O que é uma rule

Um arquivo `.md` que documenta um padrão que o agent deve seguir. O Claude Code carrega as rules automaticamente; você não precisa invocá-las. Elas ficam em dois lugares:

- **Rules do workspace**, em `.claude/rules/` do repo Workflow. `investigation.md`, `git-and-envs.md` e `prod-and-infra.md` carregam sempre; `back.md`, `front.md` e `worker.md` carregam quando você mexe naquele repo.
- **Rules do repo**, em `<repo>/.claude/rules/` dentro de cada repo de produto (`back/`, `front/`, `worker/`).

## Quando escrever uma

- Um padrão foi violado e teve que ser corrigido em review.
- Um gotcha levou horas para ser debugado.
- Uma convenção não é óbvia a partir do código.

## Formato

```markdown
---
description: One-sentence summary. Starts with "Apply when..." so the agent knows the trigger.
---

# <Rule name>

## When this applies
<concrete scenario>

## What to do
<pattern>

## What NOT to do
<antipattern>

## Why
<reason, often linking to the incident that produced the rule>
```

## Exemplos reais

- `.claude/rules/investigation.md` (repo Workflow)
- `front/.claude/rules/node-run-flush.md`
- `front/.claude/rules/react-query.md`
- `back/.claude/rules/code-standards.md`

## Rules vs skills vs hooks

- **Rule** — orientação passiva, carregada automaticamente. O agent lê; nada força o cumprimento.
- **Skill** — procedural, acionada por gatilho. Carregada quando a task bate com os triggers.
- **Hook** — código que roda antes/depois de uma chamada de ferramenta. Pode bloquear.

Se você precisa de enforcement, escreva um hook. Se precisa de um procedimento, escreva uma skill. Para padrões a seguir, uma rule basta.
