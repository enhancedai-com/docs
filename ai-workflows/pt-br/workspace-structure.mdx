A raiz do workspace é o repo **Workflow** (`enhancedai-com/Workflow`), que guarda o tooling compartilhado do Claude Code. Os repos de produto são clonados dentro dele como repositórios git separados, com estes nomes exatos de pasta, e ficam no `.gitignore` do Workflow.

## Repos de produto

| Pasta | Repo | Papel | Branch de produção |
|---|---|---|---|
| `back/` | Flux-Prompt | Backend NestJS (API) | `main` |
| `front/` | Flux-Prompt-Frontend | Frontend React (Vite) | `main` |
| `worker/` | Flux-Prompt-Worker | Worker Temporal que executa os nós | `main` |
| `mcp/` | FluxPrompt-MCP | Servidor MCP público | `main` |
| `docs/` | docs | Docs em Mintlify (este site) | `main` |
| `memflux/` | MemFlux | Serviço unificado de memória | `main` |

`back`, `front`, `worker` e `mcp` usam `develop` (dev), `staging` e `main` (produção). `docs` só tem `main`. `memflux` tem modelo próprio (`main` mais `release/*`). Veja [Fluxo de git](/getting-started/pt-br/git-workflow) para a estratégia completa de branches.

Rode os comandos git dentro da pasta do repo que você está mudando.

## Pastas do repo Workflow

- `CLAUDE.md`, `ONBOARDING.md`: instruções do workspace e o guia de setup.
- `.claude/`: configuração compartilhada do Claude Code: `agents/`, `skills/`, `rules/`, `hooks/`, `kb/`, `tasks/`, `output-styles/`, `settings.json`.
- `.mcp.json`: os servidores MCP que o workspace carrega.
- `.env.example`: modelo do `.env` da raiz do workspace, que as skills de túnel de banco leem.
- `docker/`: a stack local (`docker/devdb/`: Postgres, Redis, Temporal, back e worker).
- `scripts/`: scripts do workspace, como `deploy-direct/`.
- `debug-playwright/`: runs E2E scriptados contra o front deployado.
- `guide/`: o site offline do workshop.

Veja [Onde cada coisa mora](./where-things-live) para os artefatos (skills, agents, rules, hooks, memory, guardrails).
