## SuperChat guide

SuperChat reads this text word for word in its system prompt.

```markdown superchat-guide
Scripting Node — Runs custom JavaScript or Python code for data transformation, parsing, logic, and calculations.
FIELDS:
- script: Complete, runnable code. Variables injected as varOne, varTwo, etc. Must produce output via console.log(). Include error handling and comments for complex logic. Use \n for newlines in strings.
CRITICAL — INPUT TYPE HANDLING:
Injected variables (varOne, varTwo, etc.) may arrive as JSON strings OR already-parsed objects depending on the upstream node. ALWAYS normalize at the top of your script:
  const data = typeof varOne === 'string' ? JSON.parse(varOne) : varOne;
Then work with `data` instead of `varOne` directly. Do this for every injected variable that might contain structured data (varTwo, varThree, etc.).
RULES:
1. NEVER redeclare injected variables (e.g., `const varOne = {...}`). This shadows the real injected input and replaces it with hardcoded data — the #1 cause of silent failures.
2. Bare expressions like `myVar;` do NOT reliably return values. Always use console.log() to emit output from the node.
3. Always use the typeof/JSON.parse guard for ANY variable that might contain structured data — upstream nodes are inconsistent about whether they pass strings or objects.
4. When extracting nested properties, use optional chaining as safety:
     data?.images?.[0]?.url
   This prevents crashes if the structure is unexpected or missing.
5. Wrap complex logic in a try/catch so malformed input doesn't silently kill the node.
TEMPLATE — Extract a value from a JSON input:
  const data = typeof varOne === 'string' ? JSON.parse(varOne) : varOne;
  const result = data?.images?.[0]?.url ?? null;
  console.log(result);
TEMPLATE — Transform and return a new object:
  const data = typeof varOne === 'string' ? JSON.parse(varOne) : varOne;
  const output = {
    url: data?.images?.[0]?.url ?? null,
    status: data?.status ?? 'unknown'
  };
  console.log(JSON.stringify(output));
TEMPLATE — Safe extraction with error handling:
  try {
    const data = typeof varOne === 'string' ? JSON.parse(varOne) : varOne;
    const result = data?.images?.[0]?.url ?? null;
    if (!result) {
      console.log('ERROR: No URL found in response');
    } else {
      console.log(result);
    }
  } catch (e) {
    console.log('ERROR: Failed to parse input — ' + e.message);
  }
COMMON MISTAKES TO AVOID:
- ❌ `const varOne = { images: [...] };` — shadows the injected variable
- ❌ `varOne.images[0].url;` — bare expression, no output; also no type guard so crashes if varOne is a string
- ❌ `return data.images[0].url;` — bare return at top level fails because the node wraps code in an async function
- ✅ `const data = typeof varOne === 'string' ? JSON.parse(varOne) : varOne;` then `console.log(data?.images?.[0]?.url);`
The single most important takeaway: ALWAYS `typeof` check and `JSON.parse` your injected variables before accessing nested properties, and ALWAYS use console.log() for output.
```
