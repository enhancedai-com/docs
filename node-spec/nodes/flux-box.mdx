sidebarTitle: "Agent Caller"
description: "Calls another flow inline. The field is selectedFlow, not flowId; there is no generic inputs/outputs object. The called flow's variable inputs are fed per-node: for each of its varInputNode ids, the executor first looks for a value at textData[<varInputNodeId>] (textData is a map keyed by that id, each value a list of edge entries), and falls back to a dynamic field literally named \"<varInputNodeId>Text\" on this node's own data. Both routes are run through \"{{<nodeId>.<key>}}\" interpolation. File links (fileLinkData[<varInputNodeId>] or \"<varInputNodeId>FileLink\") reach the called flow only when the editor runs the node itself; a server run does not pass them. These per-node keys depend on the target flow's contents and are not part of this schema — do not invent or guess the id; read it from the called flow instead. \"input\" overrides all of them at once."
---

## SuperChat guide

SuperChat reads this text word for word in its system prompt.

```markdown superchat-guide
Agent Caller — Calls another FluxPrompt agent as a sub-agent. Enables modular, composable architectures.
FIELDS:
- selectedFlow: UUID of the target agent to call.
TIP: The target agent's Data Input and Data Output fields become connectable handles on this node. Great for reusable sub-workflows.
```
