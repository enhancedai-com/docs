description: "Reads from and writes to HubSpot (deals, contacts, companies). It is thirdPartyIntegration with the provider fixed to 'hubspot': same panels, same fields, same execution engine, so identical configuration yields identical results on either node — they are interchangeable for reads AND writes. RUNTIME BEHAVIOUR: it executes on the server (Temporal worker), so it produces output in every trigger — canvas run, API, cron, chatbot, form and batch — and downstream nodes can consume its result. Set mode to 'pull' to read or 'push' to write; a write also needs pushAction. WHEN CREATING A NODE use the generic field names — mode and pullObjectType (lowercase plural). selectedObjectType/selectedResponseType are the legacy spellings this node stored before the panels were unified: they are still honoured for flows saved back then, and pullObjectType wins whenever both are present."
---
